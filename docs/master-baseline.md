# 제품 구현 없는 master 비교 기준

2026-10-29 사용자 요청에 따라 master의 메모 앱 구현을 제거했다. 목적은 master에서 버전별 브랜치를 만들어 kmp_agent 버전에 따른 구현 차이를 비교하는 것이다. 제품 목표·요구사항·API/업무 정책·승인 기술 목표는 변경하지 않았다.

## 제거와 보존

- 제거: androidApp, iosApp, shared, server, web의 구현·제품 테스트·실행 도구, 루트 Gradle 빌드/래퍼, 구현 전용 Unicode 데이터·생성 도구와 Gradle bootstrap 도구. 총 55개 기존 추적 파일.
- 보존: 제품 요구사항·정책·디자인 명세와 시안, 승인 설정, 하네스 고정 설치 연결, 프로젝트 검사기, 과거 검증·보고 근거와 보고 도구.
- 이전 구현: `demo/agent-0.2.0`, 커밋 `f9f36fd9c73d118b918b547460a7c9e16ff480de`. 이 브랜치의 기존 커밋은 변경하지 않았다. 브랜치 이름만으로 실제 실행 하네스의 버전·SHA·dirty 상태를 추정하지 않는다.
- 기존 미커밋 문서·도구와 `.harness`의 미릴리스 하네스 개발본은 이 보존 브랜치에 커밋됐다는 뜻이 아니다. 이번 정리 커밋에도 섞지 않는다.

## 과거 자료 해석

`current-implementation.json`의 기존 기술·파일 해시는 과거 구현 관측이다. `availability`가 현재 master의 구현 부재를 명시한다. 과거 실행 안내(runbook/try-v1), 기능 PASS, 소스·빌드 파일 참조 및 설정 정정 검사는 해당 구현이 있던 커밋의 근거이며, 현재 master에서 앱을 실행하거나 구현 완료를 입증하지 않는다. 기존 원본 로그·장부·동결 입력은 수정하지 않았다. 제품 테스트는 구현 제거 후 실행 대상이 없으므로 NOT_RUN이다.

## 버전별 비교

새 구현은 이 제거 커밋 이후의 master를 기준으로 시작한다. 같은 작업 폴더에서 브랜치만 바꾸면 Git 제외 로그·DB·빌드 출력은 분리되지 않으므로, 비교 실행은 버전별 별도 worktree/작업 폴더와 별도 실행·로그 저장소를 사용한다. 선택한 하네스의 정확한 ref/SHA·dirty 상태, 동일 요구사항 기준, 작업 대상 ID와 실제 산출물/검증을 각각 기록한다.

`sequential-settings.json`도 현재 남아 있는 문서·시안 경로와 시안 구문 검사만 유지한다. 삭제한 구현의 Gradle/iOS 실행 명령과 모듈 경로는 제거했으며, 버전별 새 구현의 실제 명령·모듈을 이후 등록한다. 과거 동결 입력·장부를 현재 작업으로 소급 갱신하지 않는다.

로컬에 남아 있던 제품 폴더 내부의 Git 제외 빌드 출력·환경 파일은 `.harness/v1/master-baseline-reset-20261029/remaining-product-files/`로 옮겨 보존했다. DB와 다른 과거 실행 기록을 삭제하는 작업은 하지 않았다. 이 로컬 보관물은 master의 추적 제품 구현이 아니다.
