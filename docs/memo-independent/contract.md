# 틈 데이터·화면 계약

이번 사용자 답변으로 확정한 개인용 메모 범위를 구현한다. 과거 제품 계약은 입력으로 사용하지 않았다.

## 화면

모든 메모·고정한 메모·휴지통 → 제목/본문 편집. 검색은 현재 목록의 제목·본문을 대상으로 한다. 고정 메모는 모든 메모 목록의 앞에 배치한다. 정렬은 최근 수정·최근 작성·제목순이다. 제목은 300자, 본문은 200,000자다. 작성 즉시 기기에 저장하며, 800ms 동안 추가 입력이 없거나 수동 동기화를 누르면 전송한다. 로컬 저장 실패 시 입력을 유지하고 실패 상태를 표시한다.

계정은 이메일·비밀번호(10~256자)로 가입/로그인한다. 앱은 로그인 전 계정 안내를 제공하고, 계정·서버별 저장소를 분리한다. 최초 로그인 후 오프라인 사용이 가능하다. 세션 만료 시 로컬 변경을 남기고 재로그인을 안내한다. 로그아웃 전 미전송 변경이 있으면 확인한다. 같은 계정·서버로 로그인하면 미전송 변경을 다시 불러온다.

## HTTP API v1

`Content-Type: application/json`. 사용자 데이터 API는 `Authorization: Bearer <token>` 필수. 비밀번호·메모·토큰을 HTTP 접근 로그에 기록하지 않는다. 다른 기기의 로그인은 기존 기기를 로그아웃시키지 않는다.

| 요청 | 입력 | 결과 |
|---|---|---|
| `GET /v1/health` | 없음 | 서비스 상태·계약 버전 |
| `POST /v1/register` | `email,password` | `token,userId,email` |
| `POST /v1/login` | `email,password` | `token,userId,email` |
| `POST /v1/logout` | 빈 객체·현재 토큰 | 세션 폐기 |
| `POST /v1/sync` | `operations` 배열 | `results,notes` |

오류는 `{error: 사용자가 읽을 문장}`. 400 입력, 401 인증, 409 중복 이메일, 413 용량, 429 인증 시도 제한, 503 저장 실패다. 요청 상한은 4MiB, 서버 배치 상한은 500개다. 클라이언트는 용량을 고려해 한 번에 최대 10개, 동일 메모당 1개씩 전송한다.

메모: `id,title,body,pinned,deleted,purged,revision,updatedAt,createdAt`. 서버가 시간·revision을 부여한다. 읽기·쓰기 SQL은 항상 사용자 ID를 포함한다.

변경: `opId,id,kind,baseRevision` 및 put의 `title,body,pinned,deleted`. kind는 `put` 또는 `purge`. 동일 사용자의 동일 opId는 결과를 재사용한다. 응답 유실 후 재전송해도 중복 메모가 생기지 않는다.

결과: `opId,noteId,status,revision`. status는 `saved/conflict/purged/purge_rejected`. 클라이언트는 아직 보내지 않은 변경의 baseRevision을 임의로 최신 스냅샷 revision으로 올리지 않는다. 동일 메모의 이전 요청을 확인한 경우에만 해당 요청이 실제 기록한 revision으로 갱신한다. 따라서 응답 유실 동안 다른 기기가 수정해도 덮어쓰지 않는다.

## 충돌·삭제

현재 revision과 요청 baseRevision이 다르면 put 내용을 별도 ID의 충돌 사본에 기록한다. 원본은 유지하며 충돌 사본은 휴지통 밖에 둔다. 요청 opId로 사본 ID가 결정되므로 재시도에도 일관된다. 전송 중 계속 편집했다면 후속 로컬 편집은 이 충돌 사본을 대상으로 이어진다.

purge는 해당 revision의 휴지통 메모에만 적용한다. 최신 수정이나 복원이 있으면 거절하고 서버 메모를 다시 보여 준다. purged 메모는 내용 없는 tombstone으로 남아 다른 기기의 삭제 전파를 유지한다. 삭제된 메모의 오래된 오프라인 편집은 새 충돌 사본으로 보존한다.

## 제외·한계

사용자가 확정한 기획에서 공유·협업은 후속 범위다. 비밀번호 복구·이메일 인증, 종단간 암호화, 백그라운드 OS 동기화는 현재 구현에 없는 기능이며, 각각을 사용자가 명시적으로 제외했다고 해석하지 않는다. 서버 공개 배포·스토어 제출·실기기 서명 배포는 미실행이다.

기기 캐시 삭제나 앱 삭제 전에 전송하지 않은 변경은 복원할 수 없다. 동일 브라우저 다중 탭 동시 편집·대규모 전체 스냅샷 최적화는 현재 보장하지 않는 구현·검증 한계다.
