# 후속 작업 개요와 의존성

제품 MEMO-MVP, 현재 범위 MEMO-MVP-R0.2-WEB(미커밋); 기획 v0.1 완료 이력은 보존한다. 상세 개발 계획·담당별 실행 작업·PR 분해는 아직 작성하지 않는다. 아래 단계는 개요이며 실행 상태의 별도 원본이 아니다.

| 순서 | 산출물·담당 | 선행 조건·차단 | 종료 판단 |
| --- | --- | --- | --- |
| 1 기획 | FEAT-001/TASK-001·FEAT-002/TASK-002, 현재 Codex | 사용자 핵심 정책 D-001~004 답변 완료 | 요구·시나리오·AC·남은 결정 문서 검토 |
| 2 디자인 명세 | 디자인 담당: 세 클라이언트 화면·상태·행동·AC 대응 | 검토된 기획과 실행 인계용 Git 버전 고정 | 로딩/빈/오류/작성/저장/불확실/갱신 실패 포함 |
| 3 HTML/CSS 시안·시각 검토 | 디자인 담당 제작, 검토 담당 별도 검토 근거 | 명세 준비 | 명세·시안·시각 검토 각각 기록, 시안만으로 PASS 불가 |
| 4 API 계약·개발 준비 | API/서버·공유 코드·Android·iOS·웹 담당 협의 | 디자인 명세·시안·시각 검토 및 확정 정책 | 계약·스택·공유 범위·로컬 실행/검증 환경 고정 |

| 7 통합 검증·PR 생성 | 검증·개발 담당 | 구현 준비·Git 버전 고정 | AC별 PASS/FAIL/NOT_RUN, 실제 연동·재시작·응답 유실 증거; PR 생성/병합/기능 완료는 별개 |

계약 고정 후 서버와 Mock UI는 소유 파일 충돌이 없을 때 병렬 수행 가능하다. 공유 코드 소유 범위를 먼저 정한다. 실제 연동 검증은 서버·공유/플랫폼 구현 모두 필요하다. 최종 UI 검증은 시각 검토된 디자인 버전이 필요하다.

사용자에게 남은 핵심 정책 질문은 없다. 기술 결정이 확정 정책을 바꾸거나 제외 범위를 넓혀야 하면 그때 추천안·대안·영향과 함께 기획으로 반환한다.

## 웹 추가의 작업·검증 범위
디자인 TASK-003/004는 D0.3-WEB으로 이어가며 기존 모바일 구조를 재사용한다. 웹 대응 명세·시안·시각 검토만 다시 확인하고 무관한 기획 완료 단계를 재실행하지 않는다. 후속 작업/PR은 공유 코드 소유, Android, iOS, 웹, 공통 서버 API와 각각의 선행 계약을 구분한다. 공유 변경은 영향 플랫폼 모두 재검증한다.
Android 장치/에뮬레이터, iOS 장치/시뮬레이터, 웹 선택 브라우저·모바일/데스크톱 크기·키보드/포커스/탐색, 공통 API 연동 검증을 각각 기록한다. 웹 기술·지원 브라우저·KMP 로직/UI 공유·소유 범위는 UNKNOWN으로 개발 준비에서 결정하며 관련 개발/최종 검증만 차단한다.

## 2026-10-20 결정 대조 후속

SRC-004로 KMP 기반 서버·앱·웹 방향을 확정했다. 위 웹 KMP 자체의 UNKNOWN은 과거 상태이며 공유 범위·UI·라이브러리 미정은 유지한다. T-001~006/V-001의 해소 가능 항목·기술 최소안·구현/검증 차단은 [v1 재개 점검](v1-readiness.md#decision-review)에 연결한다. 목록 3줄·전체 보기 미추가는 기존 결정으로 해소한다. 일반 미저장 초안의 재진입 복원(U-001)만 사용자 선택 대기다. 이번에 제품 구현·작업 재생성·기존 상태 전환은 하지 않았다.
