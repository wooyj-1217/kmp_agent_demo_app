# 새 메모앱 사용량 집계 복구

사용자 요청: 대시보드가 있는데 토큰 집계를 누락한 문제를 복구합니다. 기존 메모앱 구현·검증 완료 판정과 원본 이벤트는 유지합니다.

## 원인

메인에서 작업/실행별 usage_bindings 등록을 누락했습니다. 사용량 원본이 자동 수집돼도 선택 실행 범위의 연결 집계에는 나타나지 않았습니다. 별도로 독립 에이전트 세션 3개는 기존 model_usage 이벤트 수집에서도 빠져 있었습니다. 자식 세션의 meta.session_id는 부모 세션을 가리키므로 실제 meta.id 및 token_usage_record.thread_id를 사용해야 합니다.

## 복구 범위·실측 결과

명시적인 새 개발 요청부터 최종 완료 응답까지 root 4개 턴과 그 부모/root ID에 연결된 자식 개발 턴을 복구했습니다. 원본 세션 ID·turn ID·response ID 및 고정 원본 prefix SHA-256을 검증합니다. 기획/디자인/개발/검증이 섞인 원본 턴은 역할·단계별로 배분하지 않습니다.

- 개발 소계: **115,315,406 토큰 · 810응답**
- 일반 입력: **1,593,950**
- 캐시 입력: **113,401,472**
- 출력: **319,984** (추론 129,653은 출력에 포함)
- 메인: 88,369,759 / 484응답
- 에이전트 1: 3,691,390 / 80응답
- 에이전트 2: 5,488,163 / 92응답
- 에이전트 3: 17,766,094 / 154응답

총량은 응답별 입력+출력입니다. 캐시 입력·추론 상세와 turn/thread 누적 스냅샷은 다시 더하지 않습니다. 같은 (native thread ID,response ID)는 한 번만 집계하고 충돌은 제외합니다. 재개발 전 세션 268응답은 제외하며, 사용량 질문 이후 집계 복구 비용은 별도 소계로 표시합니다. 현재 등록된 복구 턴의 기록은 응답 완료 후 갱신됩니다. 이후 새 턴은 명시 등록 전 제외하며 확인된 복구 소계는 완전한 전체 비용이 아닙니다.

## 화면·저장

http://127.0.0.1:8782/?scope=fresh-memo 첫 화면 상단에 개발 총량과 입력/캐시/출력 및 원본 세션별 표를 추가했습니다. 집계 복구 작업은 별도 펼침에 등록된 턴의 확인된 소계로 표시하며, 미등록 턴을 포함한 전체 복구 비용으로 주장하지 않습니다. 범위는 사후 원문 요청 연결이며 기존 세부 작업별 집계와 구분합니다.

서버는 `.harness/usage-recovery/serve_dashboard.py --port 8782` 로 실행되는 로컬 읽기 전용 확장입니다. 설치본 release 원문은 수정하지 않았으며 정식 하네스 업데이트·자동 바인딩 해결로 주장하지 않습니다. 종료 후 다시 실행할 때도 이 진입점을 사용해야 합니다. `aggregate.py`는 읽기 전용이고 명시적 persist_recovered 호출만 별도 `.harness/usage/recovered-responses.jsonl`에 원본 ID/수치/해시를 추가합니다. 원본 대화 내용과 전체 원본 경로는 HTTP 집계에 제공하지 않습니다.

## 검증과 남은 범위

중복·충돌·부모/자식 식별·과거/미등록 턴 제외·prefix 변경 거부·기간 [start,end)·누적 미합산·추가 기록 멱등성·manifest 무결성 등 합성 8개 시험이 통과했습니다. 실제 원본 읽기에서는 부적합·수치 충돌 0건입니다. 같은 원본을 journal로 두 번 가져온 두번째 추가량은 0입니다.

8783 검증 화면에서 실제 Chrome으로 총량·세션 표를 확인했고 같은8782 주소에 반영했습니다. 최종8782 화면과 독립 재집계 확인은 별도 QA 증거로 연결합니다.

단계별·역할별·개별 작업별 귀속은 여전히 미확정입니다. 숫자를 맞추기 위한 과거 usage_bindings 변경은 하지 않았습니다. 새 턴은 명시 ID 등록 전 자동 포함하지 않으며 미발견 세션의 실제 누락량·전체 수집률·실제 청구액은 미확인입니다. 이 복구는 요청 범위별 집계 복구이며 범용 실행 자동 연결 기능의 정식 수정·배포가 아닙니다.

제품 source 26개 SHA-256은 최종 빌드 manifest와 모두 같음을 복구 작업 중 재확인했습니다. 앱 테스트를 반복 실행할 변경은 없습니다.

최종 실제8782 Chrome 화면에서 총량/표/확인된 복구 소계·제외 한계 문구를 확인했습니다. 독립 QA는 원본 직접 재합산, 8개 시험, 최종 캡처·코드 대조를 통과해 usage-recovery-qa.json/md를 동결했습니다. 최종 캡처는 usage-dashboard-final.jpg 및 usage-dashboard-limits.jpg 입니다.
