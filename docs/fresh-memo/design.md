## 접근성·플랫폼 입력·탐색

- 공통: 44×44px 이상 조작 영역, 색만으로 상태 표현 금지, 제목/본문/검색 명시 레이블, 저장 상태 live polite, 오류 alert. 텍스트 200% 확대에서 필수 행동 유지. 글자수는 보조 정보.
- Web: DOM 순서 탐색→새 메모→검색→목록→편집 도구→제목→본문. Tab/Shift+Tab, Enter/Space. 포커스 3px outline. 항목 선택 시 제목 또는 편집기 heading으로 포커스, 닫으면 원래 항목으로 복귀. 확인 대화상자는 focus trap/Escape 취소/호출 요소로 복귀.
- Web 뒤로/앞으로: 내부 편집 진입은 이력 항목, 미저장 뒤로는 확인 후 이행. 저장 후 목록으로 복귀. 직접 진입은 목록으로 안전 복귀, 새로고침은 저장본 유지. 미저장 새로고침/탭 종료는 지원 브라우저 beforeunload 경고. 해당 실제 구현은 제품에서 검증.
- iOS: safe area 위·아래 적용, 키보드 회피, Dynamic Type, VoiceOver 레이블. 뒤로/스와이프 이탈에 같은 미저장 정책.
- Android: 시스템 뒤로는 키보드 닫기→편집 이탈, 미저장 확인 적용. IME inset·TalkBack·글자 확대 지원.
- 스크롤: 데스크톱 목록/편집 각각 독립, 목록 복귀 시 검색어·위치 보존. 모바일 하나의 화면만 표시하여 이중 스크롤 회피. 시안은 네이티브 실행 증거 아님.

## 인계·남은 결정

사용자가 선택권을 위임했으며, 이후 순서 지적을 반영해 독립 QA 재검토를 먼저 마친 뒤 최종 채택을 별도 selection.md에 기록한다. 현재 A-r5는 후보이며 확정안이 아니다. 브랜드·색·간격은 가역적 제안. 저장 정책은 기획의 명시 저장을 유지한다. 공통 도메인/저장 로직은 선택과 독립적으로 개발 가능하다. UI 최종 인계는 방향 선택, 상태 DOM·실제 인터랙션 완성, 독립 브라우저 시각 검토 뒤에 수행한다. 외부 메시지/전송 없음. 새 근거 없는 시행착오 항목은 작성하지 않는다.

## A-r3 동결 해제와 확인창 보완

동결 해제 이유: A-r2의 브라우저 기본 confirm이 실제 독립 QA 자동화 CDP를 차단하여 재검토가 timeout됐다. 메인의 명시 지시에 따라 r2를 보존하고 신규 r3로 교체했다. 이 변경은 검토 환경 차단 해소와 실제 제품의 사용자 정의 확인창 방향을 맞추기 위한 것이다. 기존 r2 및 r1은 수정하지 않았다.

A-r3는 window.confirm 호출을 전부 제거하고 SCREEN-004 HTML dialog를 사용한다. 미저장 이탈은 “계속 편집”/“변경 버리기”, 영구 삭제는 “취소”/“영구 삭제”. 대화상자 제목·설명은 aria-labelledby/aria-describedby로 연결하며 STATE-007/008을 구분한다. 열 때 취소 버튼에 포커스, Tab/Shift+Tab은 두 버튼 안에서 순환, Escape는 취소, 닫을 때 연결된 호출 요소로 포커스 복귀한다. 배경은 showModal에 의해 inert 처리된다. 선택 결과를 Promise로 받아 파괴 동작을 확정 이후에만 실행한다.

A-r3 JavaScript 구문 검사 PASS, window.confirm 호출 없음 소스 확인. 실제 브라우저 dialog·포커스·키보드·캡처 재검토는 독립 QA에 요청했다. 최종 후보 채택과 새 해시 동결은 메인의 QA 접수·selection.md 기록을 따른다. 작성자 수정만으로 PASS를 선언하지 않는다.


## A-r4 동결 해제·버린 초안의 데스크톱 표시 수정

메인 실제 UI 검토에서 새 메모의 입력을 버린 뒤 목록은 원래 4개로 돌아왔으나 데스크톱 편집 필드에 버린 제목이 남고 “저장됨”이 표시되는 결함이 발견됐다. 독립 QA도 closeEditor/setFilter의 draft=null 이후 입력 UI가 남는 경로를 소스에서 확인했다. 시안 제한으로 처리하지 않고 r3를 보존한 r4에서 수정했다.

현재 검토 기준은 [A-r4](prototype/memo-harness-275b489-A-r4.html)다. closeEditor의 변경 버리기 확정 후 기존 선택 메모의 저장본을 다시 바인딩한다. 새 메모처럼 저장된 선택 항목이 없으면 첫 활성 메모의 저장본을 보여준다. 활성 메모가 없으면 제목/본문을 비우고 읽기 전용 처리, 저장 비활성, “선택한 메모 없음”으로 표시한다. 모바일에서는 목록 복귀를 유지한다. 필터 이동·삭제 이후에도 동일한 저장본/빈 편집기 복구 함수를 사용하여 초안과 저장 상태 표현을 일치시킨다.

A-r4 JavaScript 구문 PASS. 메인이 r3 모바일에서 실제 관측한 기존 실패 복구·44px 버튼·가로 넘침 없음은 r3에 한정한 근거이며 r4 최종 PASS로 확대하지 않는다. r4 실제 UI 동작은 메인 검토 후 독립 QA가 증거를 해석하는 방식으로 기록한다. QA 브라우저 연결 timeout으로 직접 재실행하지 못한 범위는 NOT_RUN으로 유지한다. 작성자 변경 후 이 문서와 r4를 동결하며 최종 채택·제품 UI 착수는 메인의 검토 접수와 selection.md 기록을 따른다.


## A-r5 동결 해제·첫 사용/로딩 fixture 정합성

메인 실제 r4 검토에서 첫 사용 안내와 “메모 4개”·기존 편집기가 함께 표시되는 불일치가 발견돼 새 후보 r5로 보완했다. r4는 보존한다. 첫 사용은 독립 빈 fixture notes=[]로 전환해 0개·선택 없음·빈 읽기 전용 편집기·저장 비활성을 일치시킨다. 새 메모는 첫 사용의 빈 데이터에서 시작하며 저장 전 목록 0개, 명시 저장 성공 후 1개가 된다. 로딩도 빈 데이터·빈 비활성 편집기, 개수 대신 “불러오는 중”, 검색/새 메모 비활성으로 잔상을 제거한다. 정상 선택은 보관한 정상 fixture와 저장본 편집기로 돌아온다. 실패 상태는 초안 입력과 편집기를 유지하며 인접 재시도로 복구한다.

현재 검토 입력: [A-r5](prototype/memo-harness-275b489-A-r5.html). 구문 검사 외에 실제 HTML의 JavaScript를 Node VM과 최소 DOM 어댑터에서 실행하여 첫 사용 0개/읽기 전용·저장 비활성, 첫 메모 1회 생성, 로딩 잔상 없음·검색 비활성, 정상 4개 복귀, 검색 결과 0개/지우기, 빈 휴지통, 실패 입력 보존/저장본 불변/재시도 성공을 모두 확인했다. 근거: `.harness/fresh-memo/r5-state-logic-check.log`, 실행 코드 `.harness/fresh-memo/r5-state-logic-check.cjs`. 이는 실제 상태 함수의 논리 확인 PASS이며 브라우저 렌더링·포커스·접근성 PASS를 대신하지 않는다. 메인이 r5 실제 UI를 다시 검토하고 독립 QA가 캡처/동작 증거를 검토한다. 최종 채택은 아직 후보이며 메인 selection.md 기록을 기다린다. 이 수정 이후 문서·r5를 동결한다.
