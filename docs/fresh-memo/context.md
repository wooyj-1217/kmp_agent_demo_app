# 여백 변경 작업의 맥락

다음 작업의 진입점이다. 현재 기준·미해결·유지할 동작만 읽고 관련 명세·코드·작업 기록으로 이동한다. 과거 설치·검증 상세는 [보존 이력](../work-items/2026/2026-10-30-harness-operations-history.md)에 있다.

## 사용자 결정과 미해결

| 항목 | 현재 기준과 다음 작업 |
| --- | --- |
| 지원 플랫폼 | 사용자 확정: iOS·Android·Web. [원래 요청](request.md)에 따라 세 플랫폼 영향을 확인한다. |
| 제품 기준 | 이전 제품과 독립해 새로 만든 여백이 수정 기준이다. 이전 제품 비참조 지시를 현재 여백 맥락까지 버리라는 뜻으로 해석하지 않는다. |
| 디자인 | 사용자 위임 아래 QA 후 A-r5 채택. [선택 기록](selection.md)을 참고하되 기능 제외 승인으로 확대하지 않는다. |
| 서버·동기화 | 사용자는 기존 서버가 있으며 동기화 누락을 지적했다. 로컬 전용·서버 없음은 승인된 제품 정책이 아니다. 현재 서버 동기화는 미구현·미해결이다. |
| 서버 계약 | 서버 위치·API·인증·소유권·충돌 처리·로컬 데이터 이전은 미확인. 기존 서버를 조사하고 핵심 미결정만 묶어 확인한다. 새 서버·로그인 방식을 임의로 정하지 않는다. |
| 과거 자료 | 사용자 허용으로 `.harness/fresh-memo/discarded` 삭제 완료. 옛 보관 폴더 링크는 없으며 Git 이력은 유지한다. |
| 에이전트 운영 | 메인 중심·필요시 위임, 의미 있는 변경 종료 시 실제 맥락 정리와 메인 검토. 전체·담당 계획과 필수 답변 대기, CMD 체크리스트·대시보드 시작 확인은 [운영 지침](../agent-workflow.md)을 따른다. |

후속 사용자 발화의 정확한 원문 ID는 이 문서에 미연결(`UNKNOWN`)이다. 사용자 확정·에이전트 제안·구현 사실을 구분하고 원문·기존 수집 기록을 재작성하거나 ID를 만들지 않는다.

## 현재 구현과 변경 영향

- 제품 구현 기준은 `a1b644087448fc56f2e373462ec0b39c33a59595`다. 새 작업에서 실제 HEAD·작업 트리를 확인하며 고정 최신값으로 간주하지 않는다.
- [요구사항](requirements.md)·[디자인](design.md)과 실제 코드를 기준으로 수정한다. `shared/src/commonMain/kotlin/dev/yeoback/domain/Memo.kt`는 모델·검색·정렬·저장 정책·`YEOBACK:1:` 코덱, `composeApp/src/commonMain/kotlin/dev/yeoback/app/App.kt`는 공통 UI다. 저장소 쓰기 성공 후 메모리에 반영한다.
- Android는 임시 파일 쓰기·동기화 후 교체, iOS는 Documents 파일 원자적 쓰기다. iOS UI 테스트는 별도 파일을 쓴다. [과거 개발 계획](development-plan.md)의 SharedPreferences 설명은 현재와 다르다.
- Web은 브라우저 로컬 저장·서비스 워커 캐시다. 앱 자원 서버 8102와 대시보드 8782를 동기화 백엔드로 추정하지 않는다.
- 변경 요청이 없으면 제목·본문·줄바꿈·문자·빈 메모 정책, 명시적 저장·미저장 이탈 확인, 고정·정렬·검색·휴지통·복원·메타데이터, 저장 실패 시 입력 보존·재시도, 좁은 화면 조작과 Web 탐색·포커스 복귀를 유지한다.
- 동기화 추가 시 데이터 보존·이전, 오프라인·실패·충돌·삭제 전파와 사용자별 격리를 별도로 다뤄야 한다.

## 검증과 작업 기록

[과거 결과 보고](result.md)는 당시 로컬 구현의 근거다. 서버 동기화나 제품 전체 요구 완료로 확대하지 않고 새 코드·요구에 과거 PASS를 승계하지 않는다.

[산출물 관리](../artifact-policy.md)에 따라 시작 시 기준·범위·관련 계약·유지 동작·미결정을 [작업 기록](../work-items/README.md)에 고정한다. 종료 시 현재 명세·맥락을 갱신하고 실제 맥락 정리 담당의 변경을 메인이 검토한다. 미완료는 재개 지점·차단 이유를 남긴다. [커밋 규칙·훅](../commit-policy.md)을 따르며 로컬 훅은 새 clone 재설치가 필요하고 우회 가능하다.

최신 사용자 결정에 따라 검증 원본은 기존 로컬 경로에 보존하고 Git·PR·원격에 업로드하거나 삭제·이동하지 않는다. PR에는 코드·문서와 검증 명령·결과 요약만 남긴다. 과거 증거 전체는 일반 실행의 필수 입력이 아니며 필요한 현재 검증을 수행한다. 버전업 점검은 목록·중복·참조 확인이며 실제 삭제·이동은 별도 명시 지시가 필요하다([보존 규칙](../artifact-policy.md#에이전트-수정-증거의-수명-주기), [이전 결정과 정정](../work-items/2026/2026-10-30-agent-evidence-retention.md)). 원격 보관·복구 도구는 채택하지 않는다. 메모리·공통 적용의 실제 진행은 [정리 작업 기록](../work-items/2026/2026-10-30-memory-history-rollout.md)에서 확인한다.

## 현재 하네스 상태

토큰·작업 대시보드는 [로컬 조회기 기록](../work-items/2026/2026-11-01-dashboard-loading.md)을 따른다. 기존 집계를 먼저 표시하고 명시 조회로 갱신하며 자동 변경 알림은 미구현이다. 캐시 없는 범위의 첫 집계 지연과 현재 턴 토큰 수집 여부는 별도로 확인한다.

현재 선택 설치는 사용자 요청으로 정식 `v0.3.0` 태그(`275b489fda59d4904031ae8fb445f845485603c6`)로 되돌렸다. 설치·실제 HEAD·clean 상태와 정적 연결 PASS를 확인했다. startup 재로드 `NOT_RUN`·runtime `RESTART_REQUIRED`이며 새 프로젝트 세션에서 실제 startup·hook 검증이 필요하다. 이전 개발 커밋의 버전 필터·managed 게이트 적용 주장은 현재 설치의 기능 근거로 사용하지 않는다. [되돌리기 기록](../work-items/2026/2026-10-30-harness-v030-rollback.md)을 따른다.

공통 완료 증거·병렬 소유권·재개 보강은 [별도 작업 기록](../work-items/2026/2026-10-30-pstack-verification-reliability.md)을 참조한다. 로컬 공통 커밋만 준비됐으며 앱 제품·선택 설치·startup 제한은 위 상태를 유지한다.

공통 도구의 잠금 대기 진단·실제 모델 격리 실행 후속은 [검증 기록](../work-items/2026/2026-10-30-pstack-native-followup.md)을 참조한다. 격리 CLI 생명주기·관측 실패별 재시험 통과와 전체 회귀 원본의 실패를 구분하며, 여백 앱 설치·startup 상태는 변경하지 않았다.
