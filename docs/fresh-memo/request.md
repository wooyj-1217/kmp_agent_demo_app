# 새 메모앱 요청과 결정

사용자 원문: “야 지금까지 만든거 다 폐기하고 새로 기획부터 개발까지 메모앱 개발해. 0.2.0 참고하지말고 독립시행으로 기획부터 새로 작업 시작해.”

플랫폼 질문에 대한 사용자 답변: “iOS, Android, Web 모두 지원”. 중단 후 지시: “계속 진행해”. 원문 메시지 ID는 신뢰된 수집 기록에서 확인 전 UNKNOWN이다.

새 기획·디자인·구현을 `docs/fresh-memo` 기준으로 진행한다. 이전 제품 소스·기획·검증 결과는 새 제품의 입력/완료 근거로 사용하지 않는다. 기존 플랫폼 도구와 빌드 설정은 실행 환경으로만 확인한다. 사용자 요청에 따라 이전 제품 소스는 활성 빌드에서 폐기하고 별도 로컬 보관한다. Git 이력·하네스·수집 로그는 제품 입력이 아니므로 보존한다.

가역적 제안: 제품명 여백/YEOBACK. 회원가입 없는 로컬 텍스트 메모, 명시적 저장, 검색, 고정, 휴지통과 복원. 기획자 제안을 사용자 확정으로 표시하지 않는다. 실제 배포·서버·동기화·외부 전송은 현 범위에 포함하지 않는다.

실행 순서: 독립 기획 → 원문 일치 검토 → 디자인 비교·선택·시각 검토 → 새 공통 로직과 플랫폼 저장/진입 구현 → 각 플랫폼 빌드·실행 검증 → 독립 QA·보완·결과 기록.
