# FEAT-001 메모 목록 요구사항

제품: [MEMO-MVP](../../product.md). 작업 TASK-001, 담당 현재 Codex planning, 변경 범위 이 문서. 기능 목표는 앱을 열어 서버에 저장된 메모를 확인하고 조회 실패를 복구하는 것이다. 대상 사용자는 제품 지침의 가설을 따른다.

## 범위·요구사항·근거
| REQ | 내용 | 근거 수준·출처 | 진행 판단 |
| --- | --- | --- | --- |
| L-REQ-001 | 세 클라이언트에서 서버 목록 조회, 로딩·빈 목록·오류·재시도 구분 | CONFIRMED / SRC-001 | 진행 가능 |
| L-REQ-002 | 서버 생성 시각 최신순, 동률 고정 순서 | CONFIRMED / SRC-002 D-002 | 진행 가능; 동률 키는 API 계약에서 고정 |
| L-REQ-003 | 저장 성공 메모를 한 번 반영, 목록 갱신 실패만 재시도 | CONFIRMED / SRC-002 D-003 | 진행 가능; FEAT-002 연동 필요 |
| L-REQ-004 | 페이지 분할 없이 MVP의 전체 목록 조회·표시 | INFERRED / 기획 제안: 작은 로컬 검증 제품 | 진행 가능; 대량 데이터 요구 시 재검토 |

로그인·검색·수정·삭제·오프라인 동기화는 제품 공통 제외 범위. 별도 상세 화면은 이번 범위에 추가하지 않는다. 사용자 후속 디자인 지시에 따라 목록 본문은 최대 3줄 미리보기로 표시한다. 보이는 범위의 내부 줄바꿈·공백은 유지하며 저장 본문을 자르지 않는다. 종전의 목록 본문 전체 표시 요구는 이 지시로 대체한다. 별도 전체 보기 방식은 이번 변경에서 추가하지 않는다.

## 흐름·업무 정책·시나리오
| 흐름·시나리오 | 조건·행동·기대 결과 | REQ·정책·AC |
| --- | --- | --- |
| L-FLOW-01 / L-SCN-01 정상 | 앱 목록 진입 → 조회 중 표시 → 서버 결과를 정렬해 표시 | L-REQ-001,002 / D-002 / AC-001,002 |
| L-FLOW-01 / L-SCN-02 경계 | 서버 결과 0건 → 로딩 종료, 빈 목록 안내와 작성 진입 | L-REQ-001 / AC-003 |
| L-FLOW-02 / L-SCN-03 실패 | 최초 조회 실패 → 오류·재시도 제공 → 서버 복구 후 재시도하면 실제 목록 또는 빈 상태 | L-REQ-001 / AC-004 |
| L-FLOW-03 / L-SCN-04 정상·실패 | 작성 저장 성공 → 저장된 메모를 목록에 한 번 반영 → 재조회 실패 시 저장 성공은 유지하고 갱신 오류 표시 → 목록만 재시도 | L-REQ-003 / D-003 / AC-005,006 |
| L-FLOW-01 / L-SCN-05 경계 | 동일 생성 시각의 메모 여러 건 반복 조회 → 같은 순서 | L-REQ-002 / D-002 / AC-002 |

초기 조회 중 빈 상태·오류 상태로 오인시키지 않는다. 재조회 중/실패 시 이미 확인된 목록은 유지한다(INFERRED, 가역적 상태 표시 제안; 디자인 검토에서 재검토). 재시도 중 중복 조회 실행을 억제하고 늦게 도착한 이전 응답이 최신 목록을 덮지 않게 한다. API 정렬 규칙을 세 클라이언트에서 동일하게 따른다.

## 미결정·차단·인계
사용자 질문 Q-002(정렬·성공 조건)는 SRC-002로 해소됐다. 목록 레이아웃·긴 본문 표시·재조회 조작은 디자인 담당, 동률 키·응답 형식·전체 조회 한계는 API 담당이 구체화한다. 기획 진행 가능, 해당 디자인/API 확정 전 상세 구현·정확한 계약 검증은 차단한다. 기술 미정 항목은 [후속 개요](../../roadmap.md) 참조.

## 출처·버전·변경 영향
SRC-001·SRC-002는 [제품 지침](../../product.md)의 사용자 요청·답변이다. 기존 메모 예제는 입력으로 사용하지 않았다. 기획 v0.1. 최초 검토 당시 미커밋이며 제품 Git 커밋은 UNKNOWN이었다. 인계 기준은 이 문서를 포함하는 Git 커밋으로, 해시·경로·AC는 Git 제외 작업 관리 기록에 연결한다. 이번 변경은 최초 기획 작성이며 모든 AC가 후속 디자인·API·구현·검증에 전달된다. 정책 변경 시 영향을 받는 AC와 세 클라이언트 디자인·시안·API·구현·검증을 재검토한다. 담당은 후속 개요 참조. PR N/A(현재 요청에서 생성 제외).
진행 중 [디자인 명세](design.md)와 시안은 실제 제품 검증 근거를 대체하지 않는다. 실행 인계 전 명세 경로·제품 Git 커밋·AC ID를 고정한다.

## R0.2-WEB 변경 영향
SRC-003(제품 지침)은 기획 커밋 0f1851a1b237dd41781fc97bb22d1b364ea66238 이후 웹을 추가한 사용자 결정이다. 현재 요구사항 입력은 MEMO-MVP-R0.2-WEB(미커밋), [입력 해시](../../design/README.md#web-input)를 따른다. 기존 AC ID·업무 정책은 유지하며 전체 AC를 Android·iOS·웹 각각과 공통 서버 API 계약에 적용한다. 저장된 데이터의 웹 재진입·새로고침 후 조회는 재시작 검증에 포함한다. 미저장 본문·불확실 시도의 브라우저 탐색/재진입 세부 정책은 UNKNOWN으로 기획/API에 반환하며 해당 분기만 보류한다.
영향 대상은 TASK-003/004 명세·시안·시각 검토, 후속 공유/플랫폼 작업·PR·API 계약·검증이다. 기존 기획 v0.1 완료 이력은 유지하며 새 웹 실제 검증은 NOT_RUN이다. 공유 로직/UI·웹 구현 방식은 개발 준비에서 결정한다.

## v1 확정 변경 — SRC-005

일반 미저장 초안은 새로고침·앱 재진입 후 자동 복원하지 않는다. 내부 화면 이동은 기존 계속 작성/버리기 확인을 유지한다. 저장 중·결과 불확실 시도는 같은 시도 키·본문을 보존해 복구하며 새 작성과 구분한다. 뒤로/앞으로 이동으로 저장 시도를 새 키로 바꾸지 않는다. 정책·오류·정확한 글자 계약은 [공통 API 계약](../../api-contract.md)을 따른다. 추가 검증 V1-NAV-001: 일반 초안 재진입 시 비복원, V1-RECOVERY-001: 전송 중 종료/응답 유실 후 같은 시도 복구·한 건 보장. 기존 AC 13개를 유지하고 추가 분기를 별도 검증한다.
