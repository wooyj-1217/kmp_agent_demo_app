## 화면·컴포넌트
SCREEN-CREATE: 상단 목록 버튼·새 메모 제목, 중앙 상태 안내·본문 레이블·C-BODY 다중 줄 textarea·글자 수·검증 문구, 하단 저장 버튼. 제목 입력은 없다. textarea 최소 높이 260px(짧은 viewport 180px), 세로 resize·스크롤 가능, 저장 버튼은 내용과 겹치지 않는 flex footer. 본문은 시안의 `Intl.Segmenter`로 사용자 인지 글자를 세며 trim 후 계산한다. 최종 공백·유니코드 규칙은 API 계약 미정이며 시안 코드가 이를 결정하지 않는다. Segmenter가 없으면 저장 비활성·지원 안내.

최대 길이에서 입력을 강제로 잘라내지 않고 초과 수·오류를 표시한다. 입력 순간 포커스·커서 위치를 유지한다. 초기 빈 상태는 빨간 오류 대신 저장 조건 안내를 제공하고, 공백 입력·초과 입력은 오류로 표시한다.

성공은 작성 화면에 머무는 별도 상태가 아니다. 저장 결과 확인 시 SCREEN-LIST/L-SUCCESS로 닫는다. 저장 완료 뒤 조회만 실패한 경우 SCREEN-LIST/L-REFRESH-ERROR로 닫고 새 카드를 유지한다. 기획 D-003·D-004 준수.

C-UNCERTAIN에서 무기한 편집 금지를 제품의 최종 오류 복구 정책으로 확정하지 않는다. 시안은 재확인 행동을 제공하며, 장기 장애·앱 강제 종료 뒤 동일 시도 복구/잠금 해제는 기획에서 이미 API 계약 과제로 남긴 항목이다. 저장 중/불확실 상태의 뒤로가기 비활성은 동일 시도를 잃지 않기 위한 가역적 디자인 제안이며 실제 OS 탐색 처리와 계약을 함께 재검토한다.

시각 제안·구조 확인은 진행 가능. 브라우저 기반 시안 동작·시각 확인 전 시안 완료와 제품 UI 최종 인계는 차단한다. 실제 실행 인계 전 디자인 산출물 Git 버전 고정도 필요하며 이번 요청에서 자동 커밋하지 않는다. API·중복 방지·본문 검증 규칙·공유 범위는 기존 미결정대로 후속 담당이 정한다. 핵심 정책 신규 결정·변경은 없고 기획 반환 질문 없음. 브라우저 환경 문제는 제품 결함이나 공통 하네스 결함으로 단정하지 않는다.

## D0.4 사용자 피드백 반영
목록 본문 최대 3줄 미리보기, 작성 글자 수 초과 시 현재 수치만 빨간색(#9a302a)·굵게 표시한다. `/ 2,000`은 기본 보조색을 유지한다. 본문 하단의 “앞뒤 공백을 제외하고 최대 2,000자” 문구는 제거한다. 초과 오류 문구·저장 차단·공백 제거 및 2,000자 정책은 유지한다. 유효 길이로 돌아오면 수치 색상도 복귀한다. 원래 기획 커밋 이후 명시적 사용자 변경이며 해당 표시·스크롤·접근성 재검토는 NOT_RUN이다. 별도 전체 보기·제품 기능은 추가하지 않는다.

사용자 추가 피드백: 저장 버튼 아래의 “저장하려면 1~2,000자의 본문이 필요해요.” 문구도 제거한다. 빈 값·초과 입력의 저장 차단과 본문 인라인 오류는 유지한다.

## D0.4-WEB 진행 범위
입력은 MEMO-MVP-R0.2-WEB이며 기존 SCREEN/STATE/ACT·AC ID를 웹에도 유지한다. 공통 서버 API·업무 정책을 사용하며 웹 기술·KMP 로직/UI 공유는 UNKNOWN이다. 기존 D0.4 모바일 프레임은 웹 최종 디자인 또는 구현 완료가 아니다.
- 크기 대응 제안(INFERRED·가역적 디자인 선택): 모바일 360×800·390×844, 데스크톱 검토 기준 1280×900. 웹 데스크톱 제품 콘텐츠 최대 폭 960 CSS px·가운데 정렬·세로 문서 스크롤을 제안한다. 기존 단일 화면 흐름을 유지하며 창 크기 변화·200% 확대·짧은 높이에서 버튼 접근을 검토한다. 시안 CSS에는 아직 반영하지 않았고 실제 렌더링은 NOT_RUN이다.
- 웹 키보드·포커스: Tab/Shift+Tab의 논리적 순서·표시, 버튼 Enter/Space, 본문 Enter 개행, 확인창 포커스 제한·닫힘 후 복귀를 확인한다. 지원 브라우저·버전은 UNKNOWN이다.
- 브라우저 뒤로/앞으로·새로고침·직접 진입은 화면 내부 이동과 별도 검토한다. 저장된 데이터는 API 조회 기준을 따른다. 미저장 본문과 불확실 저장 시도의 탐색/재진입·복구 계약은 UNKNOWN으로 기획/API에 반환하고 해당 동작 확정·최종 검증만 보류한다.
- 명세 IN_PROGRESS / 시안 IN_PROGRESS(D0.4 재사용; 웹 크기·탐색 미반영) / 시각 검토 NOT_RUN. 기존 검토를 새 버전의 완료 근거로 사용하지 않는다. HTML/CSS는 샘플 시연이며 실제 웹 제품·API 연동·세 플랫폼 검증은 NOT_RUN이다.

## 웹 시안 추가 — 사용자 요청
기존 [시안 진입](prototype/index.html)에서 웹·모바일을 모두 제공한다. 기본은 반응형 웹 레이아웃이다. SCREEN/STATE/ACT ID·업무 정책은 모바일과 동일하다. 브라우저 너비에 따라 자동 배치한다. 웹 기준 viewport 1440×900·1280×800, 앱 프레임 가변 폭. 목록은 최소 240px 카드 자동 그리드, 작성은 최대 832px 중앙 영역·textarea 최소 340px, 하단은 행동 버튼과 보조 문구를 가로 배치한다. 1,000px 이하 검토 도구는 아래로, 600px 이하 목록 한 열·제품 하단은 세로 배치, 600px 이하 높이는 문서 스크롤한다. 사용자 요청의 웹 디자인 범위만 추가하며 웹 제품 기술·구현 작업은 미정이다. 실제 렌더링·상태 전환·접근성 검토는 NOT_RUN.

## v1 인계용 적용 우선순위 — SRC-005

현재 채택 기준은 본 문서의 최신 사용자 반응형 변경(D0.4-WEB)과 실제 공용 CSS/JS다. 이전 960px·고정 프레임·선택 장치 관련 제안은 이력으로 한정한다. 목록 3줄·독립 전체 보기 미추가, 작성 초과 수치만 빨간색·두 하단 조건 안내 제거를 유지한다. 토큰은 기존 가역 제안을 유지한다. 일반 미저장 초안의 새로고침/재진입 자동 복원은 없고, 화면 내 취소 확인은 유지한다. 저장 중/불확실 시도는 별도 복구 계약으로 보존하며 새로고침으로 새 작성에 진입하지 않게 한다. 앱 강제 종료를 UI로 막는다고 약속하지 않는다. 실제 영속/복구 검증은 제품 구현에서 수행한다. 최신 시안 검토의 공식 결과·테스트 출력 해시는 `.harness/v1/reviews/`와 기존 작업 원장의 V1-DESIGN에 연결하며 이전 PASS는 승계하지 않는다.
