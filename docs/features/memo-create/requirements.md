# FEAT-002 메모 작성·영속 저장 요구사항

제품: [MEMO-MVP](../../product.md). 작업 TASK-002, 담당 현재 Codex planning, 변경 범위 이 문서. 목표는 짧은 본문을 한 번 저장하고 서버 재시작 뒤에도 조회하는 것이다. 대상 사용자는 제품 지침의 가설을 따른다.

제외 범위는 제품 지침 참조. 작성 취소는 목록으로 돌아가는 보조 흐름이며 임시 초안의 재시작 복원·오프라인 저장 큐는 이번 수용 범위에 추가하지 않는다. 단, 불확실 저장 시도 식별 정보의 복구는 중복 방지를 위한 계약 설계 과제다.

## 미결정·차단·인계
Q-001(본문)·Q-003(중복)은 SRC-002로 해소. 미결정은 기술 세부 사항이며 사용자 핵심 정책을 재질문하지 않는다.
- API 담당: 동일 시도 식별·결과 재확인 방법·보존 기간·오류 분류·타임아웃, 앱 강제 종료 후 불확실 시도 식별 복구 및 잠금 해제 절차를 계약에 명시. 중복 방지 보장과 충돌하면 기획으로 반환. 해당 계약 전 관련 구현·최종 검증 차단.
- 디자인 담당: 저장 중·확실한 실패·불확실·성공 후 목록 갱신 실패를 서로 구분하고, 불확실 상태에서 앱 재진입 시의 복구 안내를 설계. 미저장 작성 취소/이탈 안내는 가역적 UI 제안으로 검토.
- 개발 준비 담당: KMP 공유 범위·플랫폼 UI·서버 영속화 기술 선택. 지금 기획 차단 없음.

## 출처·버전·변경 영향
SRC-001·SRC-002는 [제품 지침](../../product.md)의 사용자 요청·답변이다. 기존 메모 예제는 입력으로 사용하지 않았다. 기획 v0.1. 최초 검토 당시 미커밋이며 제품 Git 커밋은 UNKNOWN이었다. 인계 기준은 이 문서를 포함하는 Git 커밋으로, 해시·경로·AC는 Git 제외 작업 관리 기록에 연결한다. 이번 변경은 최초 기획 작성이며 모든 AC가 후속 디자인·API·구현·검증에 전달된다. 정책 변경 시 영향을 받는 AC와 양 플랫폼 디자인·시안·API·구현·검증을 재검토한다. 담당은 후속 개요 참조. PR N/A(현재 요청에서 생성 제외).
디자인 명세·시안은 아직 없으며 가짜 링크나 검증 근거를 만들지 않는다. 실행 인계 전 명세 경로·제품 Git 커밋·AC ID를 고정한다.
