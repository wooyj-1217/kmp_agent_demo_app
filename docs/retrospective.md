### RETRO-005 — v1 실제 구현·검증과 환경 경계

중단 후 사용자 Xcode 재설치 요청에 이어 확인한 전체 Xcode26.6은 Apple SDK 라이선스 미동의 상태였다. 에이전트가 동의하지 않고 사용자 직접 절차로 인계했으며 프로젝트 plist 검사 PASS를 Swift/iOS 빌드 성공으로 대체하지 않았다. V1-IOS 소스·프로젝트·실행 ID는 보존하고 SDK/컴파일/시뮬레이터는 NOT_RUN으로 유지한다. 요청·정확한 파일 해시·도구 종료 근거는 `.harness/v1/xcode-reinstallation-check.json`, 최신 진행은 [v1 점검](v1-readiness.md) 참조. 현재 제품 코드와 운영 수정은 dirty이며 입력 baseline 커밋에 포함된 구현으로 표현하지 않는다.

RETRO-005 후속(2026-10-20): 사용자가 라이선스 동의를 마친 뒤에도 CoreSimulator 구성 요소와 iOS 런타임이 없어 빌드가 차단됐다. 공식 first-launch·플랫폼 설치 후 프레임워크와 앱을 빌드했고, arm64 프레임워크를 x86_64로 링크한 설정 오류는 지원 아키텍처 명시로 바로잡았다. 실패 이력을 지우지 않고 XCTest 시뮬레이터 2건 성공(실패0)과 실기기·접근성·전체 AC 미검증을 분리했다. SDK 존재·설정 검사만으로 앱 실행 가능을 판단하지 않고 실제 앱 빌드와 UI/API 테스트까지 확인해야 한다. 근거는 ios-test-summary.json 및 reviews/ios.json에 연결한다.

### RETRO-006 — 핵심 저장 성공과 전체 인수 검증의 차이

2026-10-20 V1-INTEGRATION / `8c6b37ed-67b3-43f9-b250-6ae3221ca483`. 기존 단순 저장 시험의 PASS만으로 전 플랫폼 장애·접근성 인수를 완료할 수 없었다. 실제 HTTP/SQLite 앞에 지연·확실한422·커밋 후 응답 유실을 주입하고, 앱 프로세스 종료 시각과 실제 응답 시각을 대조했다. 이 과정에서 iOS 오류/키보드가 저장 버튼을 가리는 문제, Dynamic Type·대비·힌트 잘림·날짜 라벨, Android 밝은 시스템 바 아이콘, 웹 템플릿 들여쓰기 제거가 본문 내부 공백까지 바꾸는 문제를 발견했다. 기존 정책과 호환되는 표시·문자 보존 수정 후 해당 분기만 집중 재검증하고 실패 원본을 보존했다.

공통·서버의 변경 없는 검증은 재사용하고, 변경된 UI 전체에 과거 PASS를 승계하지 않았다. 실제 Chrome200%와 축소 viewport, XCTest 앱 접근성 감사와 실제 VoiceOver 읽기, OS 키보드 외부 발견을 구분한다. 소스/바이너리 SHA·시험별 결과·남은 조건은 [인수 현황](v1-acceptance-status.md) 및 `.harness/v1/`에 연결한다. 아직 미검증인 보조기술 세션을 이유 없이 PASS로 바꾸거나 전체 완료로 보고하지 않는다.

2026-10-21 직접 사용 후속: 기존8080 프로세스의 저장소 경로/메모 서버 진입점을 확인해 재사용하고 데이터 초기화 없이 지정 Android/iOS 시험 대상에만 설치·실행했다. 회귀 시험은 반복하지 않았다. 원본 실행 대상·소스/바이너리 SHA·실행 결과와 UI 도구의 Android 화면 대조 한계는 `.harness/v1/local-preview-20261021/execution.json`에 보존한다. 서버·앱·웹은 사용자 직접 사용을 위해 켜둔다. 이 실행 준비를 v1 전체 인수 PASS로 승계하지 않는다.

### RETRO-007 — 기능 검증과 디자인 적합성 검증의 누락

2026-10-21 사용자가 Android와 iOS·웹의 화면 차이를 발견해 수정 검토를 요청했다. 요구 범위 변경이 아니라 기존 승인 기준의 구현 누락에 대한 CORRECTION으로 기록했다. V1-DESIGN-CONFORMANCE / `a2ab2bff-c8c4-47cf-8437-7f30196e940d`, 실제 원문·개입 이벤트는 `.harness/v1/design-conformance/intervention-resolved.json`에 연결한다. 기능 시험은 저장·중복 방지·복구 및 일부 글꼴/접근성 조건을 확인했지만, 승인 시안과 실제 플랫폼별 상태 화면의 버튼 위치·형태·색상·간격을 비교하는 행렬이 없었다. 과거 디자인 입력 검토와 제품 UI 적합성 통과를 혼동하면 안 된다.

최신 D0.4 공통 CSS/JS의 적용 우선순위를 먼저 확인하고 네이티브 기본 타이틀/버튼 배치, 입력·카드·힌트·카운터·오류 표현을 수정했다. 상태별 실제 네이티브 캡처에서 Android·iOS의 긴 본문이 입력 영역을 늘리는 추가 결함과 iOS 내부 스크롤의 키보드 내림 누락을 발견해 보완했다. 웹의 모바일 헤더24px를 덮어쓰던28px 규칙도 제거하고 최종 상태 캡처를 갱신했다. 구현 내용과 각 실제 검증/실패 및 재검증은 [디자인 적합성](design-conformance.md)에 연결한다. OS 기본 글꼴·안전 영역·키보드·표준 취소 확인과 구현 누락을 구분하고, 현재 기술적 적용 판단을 과거 승인된 플랫폼 예외로 소급하지 않는다. 설치된 공통 하네스는 수정하지 않았다. 전체 v1 인수와 실제 보조기술 검증은 별도이며 미검증을 보존한다.

## RETRO-009 — 포괄 기술 위임을 명시 합의 변경으로 확대한 오류
