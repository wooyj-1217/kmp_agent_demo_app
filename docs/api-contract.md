# MEMO-MVP v1 실제 API·업무/복구 계약

버전 /api/v1. 로컬 전용·무인증, D-001~004·SRC-005 원본은 product.md와 두 requirements.md. 클라이언트는 입력/표시/전송·시도 복구, 서버는 최종 검증·시각/ID 생성·정렬·원자 저장·동일 시도 판정 책임을 진다. JSON UTF-8; 날짜는 UTC ISO-8601. 서버 ID는 0으로 채운 증가 정수 문자열, createdAt 내림차순 후 ID 내림차순. 목록 응답 순서를 모든 클라이언트가 유지한다. 저장 반환 메모는 ID로 중복 제거하고 정렬한다.

| 동작 | 요청 | 성공 | 오류/재시도 |
| --- | --- | --- | --- |
| GET /api/v1/memos | 없음 | 200 `{ "memos": [{"id":"000000000001","body":"본문","createdAt":"..."}] }` | 조회 오류는 목록만 재시도, 기존 목록 유지 |
| POST /api/v1/memos | `{ "attemptId":"UUID", "body":"본문" }` | 최초 201, 같은 키·같은 정규화 본문 재시도 200; `{ "memo": {...} }` | 422 INVALID_BODY/INVALID_ATTEMPT/MALFORMED_JSON는 확실한 미저장; 409 ATTEMPT_CONFLICT는 다른 본문 키 충돌로 자동 해제 금지. 네트워크/5xx/응답 파싱 실패는 결과 불확실 |
| GET /api/v1/attempts/{UUID} | 같은 시도 키 | 200 `{ "memo": {...} }` | 404 ATTEMPT_NOT_FOUND는 아직 없음이며 최종 미저장 아님. 고정 키/본문 POST 재전송 가능. 5xx/전송 실패는 불확실 유지 |

오류 JSON `{ "code":"...", "message":"..." }`. 잘못된 라우트 404, 지원하지 않는 메서드 405. 요청 본문은 최대 128KiB; 초과 413 REQUEST_TOO_LARGE는 미저장. 처리 완료한 POST의 422만 확실한 미저장으로 취급한다. 중복 키 조회가 있으면 정규화 본문 일치 후 기존 결과를 반환하고 다른 본문은409. SQL UNIQUE 제약과 단일 트랜잭션으로 같은 시도에 최대 한 메모. 서버는 COMMIT 성공 후에만201/200을 전송한다. DB·시도 결과는 서버 재시작 후 유지한다. 별개 작성은 새 UUID로 같은 본문도 허용한다.

## 입력 계약

사용자가 보는 글자는 Unicode 16.0 확장 자소군(UAX #29 revision 45)으로 센다. 공통 KMP 알고리즘과 Unicode 공식 GraphemeBreakTest를 사용한다. 앞뒤 공백 집합은 U+0009~000D,0020,0085,00A0,1680,2000~200A,2028,2029,202F,205F,3000. 내부 공백·LF/CRLF를 보존하고 NFC 등 추가 변환을 하지 않는다. UTF-16의 짝 없는 surrogate는 INVALID_BODY. 정규화 후 1~2,000 자소군만 저장한다. 시안의 JS trim/Intl.Segmenter는 최종 규칙이 아니며 제품은 공통 알고리즘으로 검증한다.

## 저장 시도·초안·탐색

일반 미저장 초안은 메모리만 사용한다. 화면 내 취소 시 내용 있으면 버리기 확인, 새로고침/강제 종료/재진입 후 자동 복원 없음. 보장할 수 없는 OS 강제 종료 경고를 필수 조건으로 두지 않는다.

저장 버튼을 누르면 입력 검증 → UUID와 정규화 본문을 **전송 전에** 플랫폼 영속 저장 → 편집·새 저장 잠금 → POST 순서다. 복구 기록 저장 실패 시 전송하지 않고 본문 유지·오류를 표시한다. 한 클라이언트는 해결 안 된 저장 시도 한 건만 가진다. 재진입은 해당 기록을 읽어 불확실 상태로 시작해 같은 시도를 수동 확인/재시도한다. 일반 오프라인 큐·자동 동기화는 구현하지 않는다. 동일 키·본문만 재전송한다. 성공하면 반환 메모를 한 번 반영하고 복구 기록을 정리한 뒤 목록으로 이동한다. 정리 실패는 해결된 같은 키를 남겨 안전하게 재확인하며 새 키를 자동 발급하지 않는다.

확실한 미저장422는 잠금을 해제하고 화면 내 본문 유지; 편집 후 새 저장은 새 키를 사용한다. 서버가 아직 없음404·시간 초과·장기 장애만으로 편집/새 키를 허용하지 않는다. 강제 이탈을 막는 대신 복구 정보를 보존한다. 뒤로/앞으로/직접 진입 시 복구 기록이 있으면 잠긴 작성 화면을 우선한다. 저장 성공 뒤 목록 재조회 실패는 별도 목록 오류이며 생성 요청 재전송은 하지 않는다.

## DB·마이그레이션

schema v1: memos(id INTEGER PRIMARY KEY AUTOINCREMENT, attempt_id TEXT UNIQUE NOT NULL, body TEXT NOT NULL, created_at TEXT NOT NULL). WAL·busy timeout·트랜잭션 사용, 메모와 키는 같은 행이므로 분리 커밋 없음. 존재하지 않는 DB는 스키마 생성 후 user_version=1. 다른 user_version은 자동 파괴/변환하지 않고 시작 실패한다. 일반 데이터 초기화 명령은 제공하지 않으며 테스트는 임시 디렉터리의 DB만 사용한다.
