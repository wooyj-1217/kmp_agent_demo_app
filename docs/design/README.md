# 메모 MVP 디자인 시안

현재 기준: MEMO-MVP-R0.2-WEB / 명세 D0.4-WEB IN_PROGRESS / 시안 D0.4 IN_PROGRESS / 시각 검토 NOT_RUN. 아래 D0.1·D0.4의 완료·입력 설명은 과거 범위에 한정하며 웹 추가의 인계 완료가 아니다.

## 열기

별도 설치·빌드 없이 아래 HTML 파일을 브라우저로 연다. JavaScript를 허용해야 한다. 두 진입점 모두 목록과 작성을 오갈 수 있으며 같은 로컬 CSS/JS를 사용한다.

- [목록부터 열기](../features/memo-list/prototype/index.html)
- [작성부터 열기](../features/memo-create/prototype/index.html)

파일 열기가 제한된 환경에서는 저장소 루트에서 정적 파일 서버만 실행한다. 제품 서버/API 구현은 아니다.

```sh
rtk proxy python3 -m http.server 8765 --bind 127.0.0.1 --directory docs
```

이후 <http://127.0.0.1:8765/features/memo-list/prototype/index.html> 접속. 작성 진입은 <http://127.0.0.1:8765/features/memo-create/prototype/index.html>. 종료는 실행 터미널에서 Ctrl+C. 이번 작업에서는 정적 서버를 실행하지 않았다.

## 조작

1. 제품 화면에서 **새 메모 작성 → 본문 입력 → 메모 저장**을 누르면 0.9초 저장 중 시연 후 목록으로 돌아간다.
2. 데스크톱에서는 왼쪽, 좁은 화면에서는 시안 아래의 **검토용 상태 선택 · 제품 UI 아님** 영역을 사용한다.
3. `다음 저장 시연 결과`에서 성공 / 확실한 미저장 / 불확실 / 성공 후 목록 갱신 실패를 선택한 다음 저장한다.
4. 불확실 상태에서 같은 결과를 반복 확인할 수 있다. 복구 시연은 다음 결과를 `저장 성공`으로 바꾸고 **같은 저장 결과 다시 확인**을 누른다. 입력이 잠기고 같은 시도 ID를 유지하는 표현을 확인한다.
5. 목록·작성 상태 선택은 **목록 상태 보기 / 작성 상태 보기** 버튼으로 적용한다. 작성 `저장 중` 표본은 자동 종료하지 않는다. 다른 작성 상태를 적용하여 빠져나온다.
6. 긴 목록·긴 본문 표본은 최대 3줄 본문 미리보기와 목록 스크롤 확인용이다. 빈 목록·실패·갱신 중도 직접 선택 가능하다. 성공 상태는 정상 작성·저장 흐름에서 확인한다.
7. 브라우저 창의 너비를 조절하면 같은 화면이 자동으로 재배치된다. 별도 웹/모바일·프레임 폭 선택은 없다. 샘플 초기화 또는 새로고침으로 메모리가 초기화된다.

## 범위·상태

기획 입력 `0f1851a1b237dd41781fc97bb22d1b364ea66238`, 디자인 D0.4 미커밋. 제목 없는 본문·2,000자·공백 처리·성공 조건·중복 정책은 유지했다. API·서버 스택·KMP UI 공유 방식은 결정하지 않았다.

저장·정렬·재시도·중복 방지는 **샘플 데이터를 이용한 UI 시연**이다. API 호출·서버 영속 저장·localStorage·오프라인 큐는 없다. 실제 앱 수용 기준 13개는 모두 **NOT_RUN**이다. 웹의 `Intl.Segmenter`와 `trim()`은 시안용이며 서버/양 플랫폼의 최종 글자 규칙을 확정하지 않는다.

- 명세 작성: **COMPLETE** — [목록](../features/memo-list/design.md), [작성](../features/memo-create/design.md)
- 시안 제작: **IN_PROGRESS** — 파일 작성·정적 검사 완료, 실제 브라우저 동작 미확인
- 시각·인터랙션 검토: **NOT_RUN** — 이 세션에서 연결 가능한 브라우저 없음
- [검토 보고·후속 체크리스트](review.md)

브라우저 확인 후 발견된 결함을 수정·재검토하고 세 상태를 갱신해야 한다. 이번 작업은 커밋·푸시·PR을 생성하지 않는다.

## 웹 추가 입력·D0.4-WEB 진행
현재 입력은 MEMO-MVP-R0.2-WEB(미커밋), 기준 기획 커밋 0f1851a1b237dd41781fc97bb22d1b364ea66238 이후 SRC-003과 기존 D0.4 변경을 포함한다. 아래 입력 SHA-256은 이번 수정 시 고정하며 이후 변경 시 새 버전으로 구분한다. 실제 제품 역할 인계 전 Git 버전 고정은 별도로 필요하며 초안 디자인을 일괄 차단하지 않는다.
명세 D0.4-WEB IN_PROGRESS / 기존 시안 D0.4 IN_PROGRESS / 시각 검토 NOT_RUN이다. 웹 대응 제안은 기능 명세에 기록했고 HTML/CSS/JS는 이번에 변경하지 않았다. 위 기존 COMPLETE·기획 입력 바이트 일치 설명은 D0.4 당시 이력이며 새 범위에 적용하지 않는다. 시안은 실제 웹 제품 구현이 아니다.

## D0.4 웹 레이아웃 추가
사용자 요청으로 데스크톱 웹 시안을 추가했다. 기존 index.html이 모든 화면 크기의 공통 진입점이다. 브라우저 너비에 따라 자동으로 반응하며 별도 플랫폼·프레임 폭 선택은 없다. 웹은 넓은 헤더·자동 열 수 카드 그리드·중앙 작성 영역·가로 하단 행동 배치다. 모바일은 기존 단일 열이다. 웹도 목록 최대 3줄·초과 수치 빨간색·안내 제거를 유지한다. 웹 시안 추가는 웹 제품 구현·API·플랫폼 기술 선택을 확정하지 않는다. 실제 브라우저 검토 NOT_RUN.

## D0.4 반응형 단일 시안
사용자 요청으로 시안 화면·시안 프레임 최대 폭 선택을 제거했다. 브라우저 1,000px 이하에서 검토 도구가 제품 아래로 이동하고, 600px 이하에서 목록은 한 열·저장/작성 버튼은 전체 너비로 바뀐다. 넓은 화면은 가용 폭에 따른 카드 그리드·최대 832px 작성 영역이다. 320/390/768/1280/1440px 실제 창 너비로 검토하며 실제 브라우저 검토는 NOT_RUN이다.
