> **SRC-006 정정 / 2026-10-21:** 사용자 재확인과 과거 원문 대조 결과, 목표는 **Ktor 백엔드 + KMP·Compose Multiplatform Android/iOS 앱** 및 합의한 공통/서버·클라이언트 전용 계층 구조다. 현재 HttpServer·Android View·SwiftUI·축약 모듈 구현은 이에 불일치한다. 아래 SRC-004의 “세부 기술 미정”은 당시 정리 이력이며 앞선 명시 합의를 철회한 사용자 승인으로 취급하지 않는다. 웹 UI 통일 적용 범위만 UNKNOWN이다. ## 목표·사용자·근거
- 제품 ID: MEMO-MVP. Android·iOS·웹에서 짧은 메모를 작성해 로컬 서버에 저장하고 다시 조회한다.
- 검증 목표(CONFIRMED): 작은 제품을 완주하며 기획 → 디자인 → 개발 → 검증 → PR 흐름과 공통 하네스를 검증한다. 최초 단계는 웹 범위·디자인 문서 반영이었다. 현재 SRC-005는 v1 기준 검토 후 제품·서버 순차 구현·검증을 포함한다.
- 초기 사용자(INFERRED): 로컬 실행 환경에서 짧은 기록을 남기는 앱 사용자와 세 클라이언트에서 흐름을 검증하는 프로젝트 참여자. 시장 조사·실사용자 인터뷰는 하지 않았으며 외부 서비스 출시를 전제하지 않는다. 사용자 조사나 배포 범위 변경 시 재검토한다. 기획 진행 가능.
- SRC-001: 2026-10-13 사용자 최초 요청. SRC-002: 같은 요청의 정책 질문 세 묶음에 대한 사용자 답변(추천안 모두 선택).

## 범위
포함: 메모 목록 조회, 본문 작성·서버 저장, 저장 후 목록 반영, 로딩·빈 목록·오류·재시도, 서버 및 앱 재시작 후 저장된 데이터 조회. Android·iOS·웹, KMP 활용, 로컬 서버.
제외: 로그인·수정·삭제·검색·오프라인 동기화·외부 서버 배포. 이번 검증 목표에 불필요하므로 제외하며 향후 확대 시 기획 담당이 새 요구사항으로 검토한다. 최초 기획 단계의 시안·제품 코드·서버 생성 제외는 당시 작업 범위였다. 현재 SRC-005의 구현·검증 허용 범위를 따른다. 브랜치·PR·외부 배포는 이번에 자동 생성하지 않는다.

## SRC-006 — 합의 누락 정정·기술 구조 재검토

2026-10-21 사용자 개입(CORRECTION). UI 방식 통일·Ktor 사용의 기존 합의를 재확인했고, 수집 원문에서 Compose Multiplatform Android/iOS 및 model/domain·서버/클라이언트 전용 계층과 의존 방향을 확인했다. 세부사항은 [합의 검토 E-01/E-06](agreement-review.md) 참조. 웹은 이후 추가됐으며 같은 UI 기술 적용 여부는 미확인이다.

SRC-005의 호환 기술 최소안 위임은 기존 명시 합의 변경 권한과 다르다. 에이전트 기술 문서·설정의 CONFIRMED·기능 시험 PASS는 사용자 승인 증거가 아니다.
