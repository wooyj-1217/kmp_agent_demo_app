# 서버 연동 메모 앱 제품 지침

## 목표·사용자·근거
- 제품 ID: MEMO-MVP. Android·iOS·웹에서 짧은 메모를 작성해 로컬 서버에 저장하고 다시 조회한다.
- 검증 목표(CONFIRMED): 작은 제품을 완주하며 기획 → 디자인 → 개발 → 검증 → PR 흐름과 공통 하네스를 검증한다. 최초 단계는 웹 범위·디자인 문서 반영이었다. 현재 SRC-005는 v1 기준 검토 후 제품·서버 순차 구현·검증을 포함한다.
- 초기 사용자(INFERRED): 로컬 실행 환경에서 짧은 기록을 남기는 앱 사용자와 세 클라이언트에서 흐름을 검증하는 프로젝트 참여자. 시장 조사·실사용자 인터뷰는 하지 않았으며 외부 서비스 출시를 전제하지 않는다. 사용자 조사나 배포 범위 변경 시 재검토한다. 기획 진행 가능.
- SRC-001: 2026-10-13 사용자 최초 요청. SRC-002: 같은 요청의 정책 질문 세 묶음에 대한 사용자 답변(추천안 모두 선택).

## 범위
포함: 메모 목록 조회, 본문 작성·서버 저장, 저장 후 목록 반영, 로딩·빈 목록·오류·재시도, 서버 및 앱 재시작 후 저장된 데이터 조회. Android·iOS·웹, KMP 활용, 로컬 서버.
제외: 로그인·수정·삭제·검색·오프라인 동기화·외부 서버 배포. 이번 검증 목표에 불필요하므로 제외하며 향후 확대 시 기획 담당이 새 요구사항으로 검토한다. 최초 기획 단계의 시안·제품 코드·서버 생성 제외는 당시 작업 범위였다. 현재 SRC-005의 구현·검증 허용 범위를 따른다. 브랜치·PR·외부 배포는 이번에 자동 생성하지 않는다.

## 기술·디자인 결정 시점
현재 방향(CONFIRMED / SRC-004, 2026-10-20): KMP 기반 서버·Android/iOS 앱·웹 개발. 구체적인 로직·UI 공유 범위, 타깃·UI 방식, 서버 런타임·프레임워크·DB·라이브러리는 아직 확정하지 않았다. 제품 모듈·빌드·테스트 명령도 UNKNOWN이다. 이 방향은 구현 착수나 검증 완료를 뜻하지 않는다.

이전 기술 결정 상태(아래 “웹의 KMP 사용 여부 미정”은 SRC-004로 대체된 과거 기록): KMP 활용은 기존 결정이다. 웹의 KMP 사용 여부는 미정이다. KMP 로직·UI 공유 범위·소유 담당, 플랫폼별 UI 방식·웹 기술, 서버 언어·프레임워크·DB, API 형식, 디자인 규칙·토큰은 UNKNOWN이다. 디자인 명세·시안·시각 검토와 API 계약·개발 준비 단계에서 담당자가 근거를 갖춰 제안한다. 현재 기획을 차단하지 않으며 특정 예제 스택을 자동 채택하지 않는다.

역할 간 실제 실행 인계 전 제품 Git 커밋·해당 명세 버전을 고정해야 한다. 최초 문서 검토는 미커밋 초안에서 수행했다. 커밋 전 재검토에서도 기획 검토 PASS·실제 앱 검증 NOT_RUN을 유지한다. 커밋 고정은 앱 검증 통과나 디자인 실행 완료를 뜻하지 않는다.

## 기획 커밋 이후 웹 범위 변경

MVP 지원 플랫폼은 Android·iOS·웹이며 세 클라이언트는 공통 서버 API와 업무 정책 D-001~004를 사용한다. 기준 기획 커밋 0f1851a1b237dd41781fc97bb22d1b364ea66238 이후 범위 변경으로, 현재 입력은 MEMO-MVP-R0.2-WEB(미커밋)이다. 기존 D0.2 사용자 변경도 유지한다. [변경 입력 해시](design/README.md#web-input)를 고정하고 실제 제품 역할 인계 전 Git 버전 고정이 필요하다. 초안 디자인은 계속 진행 가능하다. 기존 기획 DONE·검토 PASS는 v0.1 이력으로 보존한다.

## SRC-004 — KMP 방향 확인과 v1 기준 정리

2026-10-20 사용자 요청으로 KMP 기반 서버·앱·웹 방향을 확정했다. SRC-003의 세 플랫폼 범위·D-001~004·제외 범위는 유지한다. 공유 범위나 라이브러리가 결정됐다고 해석하지 않는다. 이번 작업은 기존 결정 대조·최소안·v1 baseline 연결안 작성이며 기존 산출물 재생성·제품 구현은 하지 않는다. 세부 분류·차단·사용자 선택은 [v1 재개 점검](v1-readiness.md#decision-review)을 따른다. 과거 검토 PASS는 이번 방향 추가와 최신 미검증 디자인 변경에 승계하지 않는다.

## SRC-005 — v1 정책 확정·구현 진행

2026-10-20 사용자 확정: 일반 미저장 초안은 새로고침·앱 재진입 후 자동 복원하지 않는다(U-001 해소). 화면 내 본문 유지·작성 취소 확인은 유지한다. 저장 중/결과 불확실한 **저장 시도**의 복구·중복 방지는 별도 계약이며 일반 초안 정책으로 폐기하지 않는다. 기술 최소안 선택·이유 기록·최신 변경 검토·통과 후 v1 baseline 활성화·개발 태스크와 순차 구현/검증을 승인했다. 요구·UX 변경만 질문하고 검증 불가 타깃은 NOT_RUN으로 남긴다. 상세 원본: [기술 결정](technical-decisions.md), [API·복구 계약](api-contract.md), [실행 안내](runbook.md). 과거 미구현·PASS 기록은 당시 이력으로 보존한다.
