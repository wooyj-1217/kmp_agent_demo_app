# 산출물과 과거 기록 관리

목표는 기록이 늘어도 다음 작업이 읽어야 하는 양을 제한하는 것이다. 현재 기준은 갱신하고, 변경 이유는 작업 기록에, 실제 변경 전후는 Git에 남긴다. 새 작업부터 적용하며 기존 자료는 관련 기능을 수정할 때 점진적으로 정리한다.

## 기록의 역할

| 구분 | 기준 위치 | 유지 내용 |
| --- | --- | --- |
| 현재 기준 | `docs/fresh-memo/requirements.md`, `design.md` 등 관련 명세 | 현재 유효한 요구·화면·동작·계약. 대체된 설명을 본문에 누적하지 않는다. |
| 시작 맥락 | `docs/fresh-memo/context.md` | 현재 결정·구현 사실·미해결·유지 동작·관련 경로. 전체 연혁을 복사하지 않는다. |
| 작업 기록 | [작업 기록](work-items/README.md) | 변경 이유·중요한 결정·결과·한계·관련 커밋과 증거. 작업 하나에 파일 하나를 사용한다. |
| 변경 이력 | Git | 코드·문서의 변경 전후. [커밋 규칙](commit-policy.md)에 따라 이유와 작업 기록을 연결한다. |
| 검증 원본 | 해당 작업의 프로젝트 로컬 증거 경로 | 실행 로그·캡처·결과 파일. 작업 기록에는 대상 버전·판정·근거 경로를 요약한다. |

`result.md`·선택 기록·과거 프로토타입 등 특정 시점의 결과물은 그 당시 근거다. 새 구현에 맞추기 위해 과거 결과를 덮어쓰지 않는다. 현행 기준으로 잘못 읽히는 자료에는 적용 시점·대체 문서 링크를 명시한다. 과거 PASS를 현재 변경의 PASS로 승계하지 않는다.

## 작업 시작과 종료

1. 시작 시 현재 맥락에서 관련 명세·코드·기존 작업 기록만 선택한다. [템플릿](work-items/TEMPLATE.md)으로 작업 기록 하나를 만들고 기준 커밋·작업 트리·영향 범위·미결정을 적는다. 이미 해당 작업 기록이 있으면 이어서 갱신한다.
2. 진행 중에는 같은 기록의 현재 상태를 갱신한다. 대화·원문 로그·명세를 복제하지 않고, 사용자 확정·에이전트 제안·구현 사실을 구분한다. 중요한 결정에는 근거와 대체하는 이전 결정의 경로·절 또는 커밋을 연결한다.
3. 종료 시 현재 명세를 유효한 기준으로 고치고, 맥락에서 해결된 항목과 중복 설명을 정리한다. 작업 기록에는 최종 결과·남은 문제·검증 범위·실제 근거를 남긴다. 코드와 문서를 나눠 커밋하면 같은 작업 기록을 연결한다.
4. 의미 있는 변경은 기존 [종료 맥락 정리](agent-workflow.md#종료-맥락-정리)에 따라 담당이 대조하고 메인이 검토한다. 미완료 종료는 완료로 표시하지 않고 재개 지점과 차단 이유를 남긴다.

종료한 작업 기록의 과거 결정·판정을 새 사실로 바꾸지 않는다. 오류 정정이나 후속 검증은 날짜·이유·근거를 명시한 정정 절에 덧붙이거나 새 작업 기록으로 연결한다. 현재 명세는 별도로 갱신한다. 마지막 커밋이 자기 SHA를 포함해야 한다고 요구하지 않는다. 알려진 커밋을 기록하고 이후 `git log -- <작업 기록 경로>`로 연결된 최종 변경을 찾을 수 있다. 없는 커밋·원문 ID·승인·실행 ID는 만들지 않고 미확인 값은 `UNKNOWN`으로 둔다.

## 규모가 커졌을 때

- 작업 기록은 처음부터 연도별 경로에 저장한다. 종료 후 기본 읽기 대상에서 제외하고 관련 기능·결정에 필요할 때 검색한다. 별도의 시간순 요약·수동 전체 인덱스를 중복 유지하지 않는다.
- 기능 묶음 완료나 제품 버전업 때 현재 문서의 중복·충돌·끊어진 경로·과거/현재 혼동을 점검한다. 큰 문서는 기능별로 나누고 진입점에는 링크만 둔다. 공통 에이전트 지침 버전업 정비와는 별도 점검이다.
- 중요한 사용자 결정과 검증 원본은 요약만 남기고 삭제하지 않는다. 재생성 가능한 임시 파일·중복 증거 정리는 재생성 방법, 사용 여부, 보존 필요를 먼저 확인한다. 이 규칙은 자동 삭제·일괄 이전 권한이 아니다.
- 검증 원본은 기존 로컬 경로에서만 확인·보존한다. 원격 보관과 별도 복구 도구는 채택하지 않는다. 증거는 PR·Git에 업로드하거나 임의 삭제·이동하지 않는다.
- Git에 없는 로컬 증거는 Git checkout으로 복구되지 않는다. 보관 경로가 없거나 읽을 수 없으면 그 한계를 작업 기록에 남기고 증거가 보장된다고 주장하지 않는다.

## 에이전트 수정 증거의 수명 주기

최신 사용자 결정(2026-10-30): 검증 증거는 로컬에서 확인·보존한다. 실제 원본 로그·캡처·검증 JSON·증거 묶음은 제품·공통 Git 커밋, PR 첨부, 원격 저장소 또는 별도 원격 보관소에 올리지 않는다. PR에는 수정 코드·문서와 검증 명령·결과 요약만 남긴다. 기존 증거는 삭제·이동하지 않는다. 이 결정은 이전 보관·정리 제안보다 우선한다.

- 작업 기록에서 관련 PR·수정 커밋·검증 대상과 로컬 근거 경로를 연결한다. PR·커밋·버전이 미확정이면 `UNKNOWN`으로 두고 보존한다. 로컬 경로는 원격에서 열람 가능하다는 뜻이 아니다.
- 에이전트 일반 실행에 과거 증거 전체를 필수 입력으로 요구하지 않는다. 필요한 검증은 현재 작업에 맞춰 로컬에서 수행한다. 과거 파일이 없으면 당시 PASS를 현재 결과로 승계하거나 원본을 확인했다고 주장하지 않는다.
- PR 준비·리뷰·수정 대응 중 증거를 보존한다. 버전업 때 해당 릴리스의 증거 목록·중복·참조 상태를 점검할 수 있으나 이 점검만으로 삭제·이동하지 않는다. 로컬 선택 커밋 설치나 서버 재시작은 릴리스 완료가 아니다.
- 중요한 최종·실패·수정·재검증 원본과 미반영·미해결 작업의 근거는 유지한다. 향후 삭제·이동은 별도 명시 지시가 있을 때만 대상·이유·처리 결과를 기록하며 수행한다.
- PR 제출 전 staged 파일·diff·본문·첨부에 원본 증거와 비밀값·개인정보가 없는지 확인한다. 과거 검증 보고서 전체를 공통 저장소로 복사하지 않는다.

버전업은 기록 점검 시점이며 증거 삭제·이동 조건이 아니다. 원격 보관·복구 도구 초안은 채택하지 않는다. [이전 결정과 정정](work-items/2026/2026-10-30-agent-evidence-retention.md), [최신 적용 기록](work-items/2026/2026-10-30-memory-history-rollout.md)을 참조한다.

## 현재 적용 범위

이 문서와 작업 템플릿은 파일 기반 운영 규칙이다. 기존 문서·증거의 일괄 이관·삭제, 외부 보관소, 검색 DB, 자동 보존·정리 기능을 구축한 것은 아니다. 기존 하네스 원문 수집·ID·완료 원장을 이 작업 기록으로 대체하지 않는다.
