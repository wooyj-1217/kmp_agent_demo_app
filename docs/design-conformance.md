## 기존 검증이 놓친 이유

기능 검사는 실제 저장/조회/키 재사용·잠금·경계값·본문 보존을 검증했다. UI 검사는 별도의 글꼴 확대·3줄·초점·부분 접근성 감사였고, 화면×상태×플랫폼의 공통 헤더/푸터·계산된 토큰·정렬을 대조하는 디자인 인수는 없었다. 캡처가 존재한다는 사실과 특정 결함 재검증을 전체 디자인 적합성 PASS로 확대하면 안 된다. 과거 기능 PASS/실패 원본은 보존하고, 이번 표시 변경에 영향을 받는 기능·접근성 결과는 최신 코드로 다시 확인한다.

기존 V1-DESIGN-REVIEW는 입력/시안의 검토 범위이며 제품 네이티브 전체 적합성 검토가 아니다. V1-INTEGRATION의 전체 NOT_RUN/BLOCKED도 유지한다. 이번 작업 V1-DESIGN-CONFORMANCE는 그 누락을 사용자 개입과 연결해 검토한다.

## 추가 대조·수정

- C-EMPTY와 C-INVALID(삭제 후 빈 입력)의 차이: 네이티브는 빈 문자열이면 항상 오류를 숨겨 초기/편집 후를 구분하지 못했다. 표시 계층에 touched 상태를 두고, 초과/공백·빈 편집 문구를 공통 시안과 맞춘다. 일반 초안 영속 보관을 추가하지 않는다.
- 실패 시 주 행동 `다시 저장`, 유효 입력/잠금의 하단 설명, 모바일의 설명→주 버튼 순서가 누락돼 복구한다. 삭제 승인된 두 조건 안내는 재추가하지 않는다.
- 원문 시안의 카드·입력 행간/placeholder·행동 아이콘을 대조해 표시만 보완한다. 버튼의 장식 glyph와 접근성 이름은 분리하고, 실패 후 수정 시 접근성 이름도 현재 행동으로 갱신한다.
- 고배율 글꼴에서 iOS 헤더/푸터를 고정해 잘리게 하지 않고 전체 내용을 스크롤하도록 한다. native Dynamic Type의 보조 문구는 검증된 footnote13pt를 사용한다(명세 보조12~13 범위). OS 글꼴·glyph/안전 영역의 픽셀 차이는 공통 배치 누락과 구분한다.

검증 과정의 빌드 오류·문자 꾸밈/중력 비트를 값 대신 객체로 비교한 테스트 오류·안정되기 전 캡처 프레임은 과거 근거로 보존하고 최종 시각 PASS에 사용하지 않는다. iOS 긴 미리보기의 옛 높이40~65pt 기준은 compact 구현의 측정치였고, baseline의15pt/27pt 행간 적용 후 실제3줄은72pt다. 기대 범위를60~90pt로 바꾸고 실제 캡처·3줄 제한·DB 원문 보존을 함께 확인한다. 검사를 완화해4줄을 승인하는 것이 아니다.

## 이번 기술 적용 판단

과거에 승인된 플랫폼 예외로 소급하지 않는 현재 검토 판단이다. Android Views·SwiftUI는 OS 글꼴과 dp/pt·안전 영역을 사용하며, 본문/카운터/주 행동의 역할·순서·색상·잠금 계약을 공통으로 적용한다. 네이티브 진행 표시는 OS progress control을 대기 notice 안에 한 번 두고, 웹은 CSS spinner를 사용한다. 네이티브 구분선은 안전한 내용 여백에 정렬하며 웹의 전체 폭 테두리와 픽셀 위치가 다르다. 기능·정보 위계를 바꾸지 않는 최소 적용으로 채택하며, 해당 차이를 시안과 픽셀 동일 PASS라고 표현하지 않는다. 네이티브의 더 큰 글꼴 설정에서는 잘림 방지를 우선해 헤더/푸터를 포함한 전체 내용 스크롤을 허용한다. 숫자의 천 단위 구분은 iOS 지역화와 Android/웹 표시가 다르지만 계산 단위·허용 범위·초과 수치 강조는 같다.

일반 입력과 긴 입력 모두 본문 영역은 기본220dp/pt로 유지하고 내부에서 스크롤한다. iOS는 긴 입력 내부 스크롤에서도 키보드가 내려가도록 처리한다. 이는 저장·일반 초안 복원·불확실 시도 계약을 변경하지 않는다.

## 연결·남은 범위

사용자 발견은 요구 변경이 아닌 CORRECTION이다. 실제 요청 source event `905b807f-bca8-4adf-85d1-ea103564e0ac`, 해결된 개입 event `f798d32d-5e77-4664-b10e-caa7678784d2`, 초기 pending 기록도 보존한다. V1-DESIGN-CONFORMANCE / `a2ab2bff-c8c4-47cf-8437-7f30196e940d`의 작업·명령·산출물·검토에 연결한다. 비용/사용량은 UNKNOWN이고, 늦게 선언한 수집 정보나 runner의 최초 code_paths 밖 범위를 소급 보완했다고 주장하지 않는다.

최신 UI로 실제 VoiceOver·TalkBack·웹 화면 읽기 세션은 NOT_RUN이다. 다른 화면 크기/OS/실기기와 전체 필수 인수도 이번 통과 범위가 아니다. 기존 V1-INTEGRATION의 BLOCKED/NOT_RUN을 보존하며 **v1 전체 완료가 아니다**. 이전 시안 입력 검토 PASS를 최신 제품 적합성 근거로 사용하지 않았다. 이번 응답의 Stop 실행/원문 수집 성공은 아직 PENDING_NEXT_TURN이며 정적 연결과 실제 수집 성공을 구분한다.

직접 확인: 기존 데이터 서버와 웹은 http://127.0.0.1:8080/ , Android는 emulator-5554 Small_Phone, iOS는 사용자 확인용 `21EDD711-E09C-441B-A415-ACE0D303C046`이다. 기존 메모6개를 유지하고 두 앱과 웹을 실행 상태로 남긴다. 최종 연결 상태 근거는 `live/environment.json`이다.
