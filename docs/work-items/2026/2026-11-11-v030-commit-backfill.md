- 요청: 이전 버전의 미추적 맥락 문서와 누락 작업을 해당 버전 브랜치에 커밋·푸시한다.
- 대상: `demo/agent-0.3.0`, 기준 `a1b644087448fc56f2e373462ec0b39c33a59595`.
- 원본: 기존 작업 폴더의 미추적 문서·검사 도구와 `stash@{0}` (`59e1c7b`)의 추적 파일 변경.
- 방법: 별도 worktree에서 stash를 apply하고 해당 버전 문서·소스·검사 정의만 복사한다. 원본 작업 폴더와 stash는 보존한다.

## 범위와 판단

`context.md`는 이전 여백 제품의 맥락이며 기존 구현 커밋에 포함되지 않았다. 이전 작업 기록도 미커밋 상태를 명시한다. 새 브랜치 전환 시 추적 변경은 stash됐지만 미추적 자료는 로컬에 남았다. 이 복구는 독립시행의 맥락 격리 실패를 소급 해소하지 않는다.

기존 코드 변경은 재시작·저장 검증을 위한 테스트 및 접근성 식별, debug 저장 격리와 검사 도구다. 정책·기획 문서는 당시 기록을 그대로 보존하며 과거 PASS를 이번 코드 전체의 새 PASS로 승계하지 않는다. `tools/*verification.json`은 실행 결과가 아니라 명령·수용 조건을 정의한 검사 입력이므로 포함한다.

새 틈 소스·문서, 설치 하네스, 개인 설정, 빌드·DB·영상·검증 원본은 포함하지 않는다. 새 기능이나 정책을 설계한 작업이 아닌 누락 커밋 전달 정리이므로 메인이 파일 목록·원본 일치·기록을 직접 확인한다. 별도 맥락 정리 담당은 호출하지 않는다.
