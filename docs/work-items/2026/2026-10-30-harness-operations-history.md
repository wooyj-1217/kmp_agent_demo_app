## 작업 시작·종료 시 갱신할 최소 맥락

시작할 때 변경 목표, 기준 커밋/작업 트리, 관련 요구·화면·데이터/API 계약, 지켜야 할 동작, 미결정 사항을 짧은 작업 문서로 고정한다. 서브에이전트에는 그 문서와 필요한 파일 경로·소유 범위만 전달한다.

마칠 때 의미 있는 변경은 맥락 정리 담당이 실제 변경·사용자 결정·남은 문제·검증 근거를 해당 기준 문서와 이 진입점에 반영하고 메인이 별도로 검토한다. 제안은 사용자 확정으로 승격하지 않는다. 미완료 시 마지막 상태·다음 행동·차단 이유를 같은 작업 문서에 남긴다.

새 커밋 준비와 산출물 갱신에는 [커밋 규칙](../commit-policy.md)·[산출물 관리 규칙](../artifact-policy.md)을 적용한다. 현재 명세·맥락은 유효한 기준으로 유지하고, 변경 이유·결정·검증·커밋은 연도별 작업 기록에서 연결한다. 현재 저장소는 `core.hooksPath=.githooks`로 메시지 검사 훅을 설치했으며 정상/오류 메시지 직접 호출과 임시 저장소의 실제 커밋 검증을 포함한 2개 테스트가 통과했다. [이번 작업 기록](../work-items/2026/2026-10-30-commit-hooks-artifacts.md)에 근거와 한계를 연결한다. 로컬 훅은 우회 가능하고 새 clone에는 재설치가 필요하며, CI·서버 강제 검사·기존 산출물 일괄 이전/삭제·별도 보관소/검색 DB는 구축하지 않았다. 공통 하네스 release나 제품 완료 상태는 변경하지 않았다.

에이전트 수정 증거는 PR 준비·리뷰 중 보존하고 버전업 때 반영된 작업의 중복·임시 증거를 검토 정리하며, 중요 원본과 미반영·미해결 근거는 유지한다([보존 규칙](../artifact-policy.md#에이전트-수정-증거의-수명-주기), [결정 기록](../work-items/2026/2026-10-30-agent-evidence-retention.md)); 이번에는 규칙만 반영했고 실제 삭제·이전이나 공통 `kmp_agent` 수정은 하지 않았다.

메인은 요청·변경 영향·기준 버전을 확인하고 조사·구현·통합·검증을 기본으로 직접 수행한다. 서로 의존하는 작은 단계에 역할별 인계 사슬을 반복하지 않는다. 범위가 분리되고 인계 비용보다 이득이 있는 조사·구현·검토만 독립 담당에게 위임한다. 공유 파일·출력·시뮬레이터 소유 범위와 통합 책임을 먼저 정한다. 필요한 필수 검토를 생략하는 근거로 사용하지 않는다.

위임 입력은 작업/실행 ID, 실제 요청·확정 결정 근거, 기준 커밋과 작업 트리, 관련 명세·코드 경로, 읽기/쓰기 범위, 유지 동작, 검증·반환 형식으로 제한한다. 전체 대화나 제품 원문 로그를 반복 복사하지 않는다. 제품 자료는 이 프로젝트에 보관한다.

공통 하네스 버전업 준비에서는 직전 실제 배포 이후 누적 지침을 지침 정비 담당이 검토하고 메인이 결과를 검토·반영한 뒤 버전을 확정한다. PR·머지마다 정비 담당을 호출하지 않으며, 현재 작업을 잘못 수행하게 만드는 충돌은 즉시 처리해 다음 버전의 누적 점검에 포함한다. 세부 계약의 기준 위치는 공통 원본 `docs/releases/README.md#instruction-maintenance`와 `docs/roles/instruction-maintainer.md`이며, 문서 절차와 자동 호출·런타임 집행 구현을 구분한다.

## 종료 맥락 정리

산출물 정리와 과거 추적은 [산출물 관리 규칙](artifact-policy.md)을 적용한다. 현재 명세·맥락은 유효한 기준으로 갱신하고, 의미 있는 작업은 [작업 기록](work-items/README.md) 하나에 이유·결정·검증·변경 연결을 남긴다. 과거 결과를 현재 결과로 덮어쓰거나 이력을 현재 맥락에 계속 누적하지 않는다. 커밋 준비에는 [커밋 규칙과 자동 검사 훅](commit-policy.md)을 적용한다.

기능·정책·데이터/API 계약·아키텍처가 바뀌면 구현과 필요한 검증 후 메인이 실제 맥락 정리 서브에이전트를 호출한다. 담당은 관련 기준 문서와 [현재 맥락](fresh-memo/context.md)을 대조하고 사용자 확정·에이전트 제안·구현 사실·미해결을 구분해 갱신한다. 과거 원문과 검토 이력은 보존하고 대체된 기준은 연결한다. 제품 코드나 핵심 정책을 이 책임으로 바꾸지 않는다.

담당은 수정 경로·현재 SHA-256·이유·남은 제안/문제와 UPDATED 또는 NO_CHANGE를 반환한다. 메인은 문서 변경을 읽고 별도 수락한다. 담당의 제안은 메인 수락이나 사용자 승인이 아니다. 단순 오타·기계적 수정은 메인이 직접 갱신하고 별도 정리가 불필요한 구체적 이유를 남길 수 있다. 정리 담당 자신에게 재귀 위임하지 않는다.

## 사용량과 완료 근거

메인은 해당 작업 실행에 정확한 native session/turn 또는 response ID를 등록한다. 독립 담당은 자식의 실제 native ID와 호출 근거를 연결한다. 이름·시간·경로만으로 귀속을 추정하지 않고 미확인 값은 UNKNOWN으로 유지한다. 원본 수집, 사용량 수치, 작업 실행 바인딩은 각각 확인하며 캐시·추론 상세나 누적 스냅샷을 추가 합산하지 않는다.

선택한 하네스의 완료 계약을 구성한 신규 작업은 사용량 연결과 맥락 정리 결과·메인 수락·현재 문서 해시를 검사한다. 기존 작업의 완료 이력을 소급 변경하지 않는다. pending·충돌·미확인은 PASS로 보고하지 않는다. 게이트는 구조적 근거 검사이며 자동 서브에이전트 생성, 제품 결정 승인, 전체 사용량 수집 보장을 뜻하지 않는다. 종료 점검 뒤 생성될 마지막 응답은 종료 수집 이후 갱신될 수 있다.
