## 요청과 범위

사용자가 웹과 앱의 시연용 동영상 촬영을 요청하고 진행을 지시했다. 앞선 앱 실행·결과 확인 요청과 별도의 영상 제작 작업이다. Web·iOS는 메모 작성·명시적 저장·고정·검색·휴지통 이동·복원, Android 최종본은 기존 시연 메모 목록·열기·휴지통 이동·복원을 보여준다. 기존 메모는 보존한다. 영상 제작은 서버 동기화 구현이나 제품 전체 완료를 뜻하지 않는다.

## 결정과 구현 사실

- Web은 CUA로 실제 앱을 조작하며 얻은 화면 30개를 바탕으로 프레임 간 표시 시간 상한을 2.5초로 조정하여 H.264 24fps MP4로 편집했다. 연속 고프레임 화면 녹화가 아니다. 시연 문구는 한글이다.
- iOS는 Simulator 실제 화면을 `simctl recordVideo`로 녹화했다. 약 67.71초 원본에서 시작 7초를 잘라 H.264 MP4로 내보냈다. UI는 한국어이며 시연 메모 문구는 영어다.
- Android는 standalone 에뮬레이터의 CUA 접근이 되지 않아 Android Studio embedded API 37을 시도했으나 OS ANR로 중단했다. API 35 Pixel 8로 전환했다. `adb shell screenrecord` 초기 MP4는 약 120.15초·720×1600으로 디코딩됐으나 네 시점 샘플이 모두 같아 정지영상으로 REJECTED 처리했다. 정상 디코딩만으로 정상 시연이라고 판단한 초기 보고는 사용자에게 즉시 정정했다. 해당 파일은 `.harness/demo-video/2026-11-01/yeoback-android-rejected-frozen.mp4`에 보존한다.
- Android는 emulator console의 `adb emu screenrecord start`로 실제 WebM을 재촬영했다. 약 85.347초·720×1600·VP9 24fps 원본의 15초 간격 샘플 여섯 개가 모두 달랐다. 임시 `/tmp`의 imageio-ffmpeg 도구로 시작 3초 제거·1.35배속·무음 H.264 MP4를 내보냈다. 최종본은 목록·열기·휴지통·복원이며 작성·검색 장면은 포함하지 않는다.
- 기기별 로컬 저장과 서버 동기화 미해결 상태는 유지한다. 별도 서버·계정 방식이나 제품 정책을 이 촬영 작업에서 결정하지 않는다.
