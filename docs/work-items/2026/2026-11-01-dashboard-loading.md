## 요청과 원인

사용자는 토큰과 작업 내역을 보려고 연 대시보드에 내용이 뜨지 않는다고 알렸다. 메인은 사용자 탭에서 선택 범위 조회 중인 빈 본문을 확인했다. 이벤트 원본은 약 405MB였으며 선택 설치 v0.3.0 조회기는 매 요청 전체 기록을 읽고 화면이 3초마다 재조회했다. 토큰 복구 집계도 요청마다 수행되어 새 접속의 초기 표시가 지연됐다.

## 결정과 현재 구현

- 사용자 요청은 대시보드 표시 복구다. 캐시 방식은 에이전트의 구현 선택이며 제품 범위 승인과 무관하다.
- 로컬 조회기에서 3초 폴링을 제거했다. 실제 집계 결과를 필터별 메모리·디스크 캐시에 보관하고 기존 결과가 있으면 먼저 반환한다. 60초 경과 후 조회하면 백그라운드에서 재집계한다.
- 캐시 키는 프로젝트 경로·실행 범위·기간·추가 필터를 포함한다. 원래 `refreshed_at`을 유지하여 과거 결과를 방금 집계한 것처럼 표시하지 않는다.
- `fresh-memo`의 초기 캐시는 `/tmp/yeoback-dashboard-status.json`에 보존된 실제 관측(`2026-11-01T05:45:27Z`)으로 준비했다. 원본 이벤트·선택 설치 릴리스·제품 코드는 변경하지 않았다.
- 조회 주소는 `http://127.0.0.1:8782/?scope=fresh-memo`다. 재실행 명령은 `rtk proxy python3 .harness/usage-recovery/serve_dashboard.py --port 8782`다.

- 메인 실제 검증: 같은 범위 API가 HTTP 200, 약 0.061820초로 응답했다. 사용자 Chrome 탭 새로고침 뒤 115,315,406 토큰·810응답과 작업 내역 표시를 확인했다. 화면 원본은 `/tmp/yeoback-dashboard-fixed.png`, API 결과는 `/tmp/dashboard-fixed.json`에 로컬 보존한다.
