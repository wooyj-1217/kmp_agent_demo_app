# 프로젝트 에이전트 운영

현재 설치 기준: 사용자 요청으로 정식 `v0.3.0` (`275b489fda59d4904031ae8fb445f845485603c6`)로 복귀했다. 아래 개발 커밋의 적용 설명은 과거 기록이며 현재 기능 지원을 뜻하지 않는다. startup·hook 재검증은 새 세션에서 필요하다. [되돌리기 기록](work-items/2026/2026-10-30-harness-v030-rollback.md)을 참조한다.

현재 수행 절차다. [이전 제안](agent-workflow-proposal.md)을 대체하며 제품 결정·과거 근거는 바꾸지 않는다. 설치·테스트·사용량의 상세 연혁은 [운영 적용 이력](work-items/2026/2026-10-30-harness-operations-history.md)에 보존했다. PR 상태 등 과거 관측은 현재 원격 상태를 뜻하지 않는다.

## 수행과 위임

메인이 요청·영향·기준 버전 확인, 조사·구현·통합·검증을 기본 수행한다. 독립 범위의 실익이 인계 비용보다 클 때만 위임하며, 짧거나 순차 의존적인 작업에 역할별 인계 사슬을 반복하지 않는다. 필수 품질 검토는 유지한다.

위임 시 작업/실행 ID·확정 결정 근거·기준 커밋과 작업 트리·관련 명세/코드·읽기/쓰기 소유 범위·유지 동작·검증·반환 형식을 전달한다. 공유 출력·시뮬레이터 소유와 통합 책임을 정하고 전체 대화·로그를 복사하지 않는다. 제품 자료는 프로젝트에 보관한다.

사용자 결정에 따라 공통 지침 정비는 매 PR·머지가 아니라 에이전트 버전업 준비 때 누적 변경을 모아 검토한다. 담당 결과를 메인이 검토·반영한 뒤 버전을 확정한다. 실행을 잘못 이끄는 충돌은 즉시 처리하고 누적 점검에 포함한다. 작업 종료의 맥락 정리와 구분하며 자동 호출·런타임 집행을 문서 계약과 혼동하지 않는다. 지침 정비 계약의 제출 당시 상태와 근거는 [보존 이력](work-items/2026/2026-10-30-harness-operations-history.md#운영-지침-원문)에 있다.

## 계획·질문 처리와 대시보드에 대한 사용자 결정

착수 시 전체 주요 계획을 제시하고 위임 담당도 담당 계획을 보고한다. 사용자 답변이 필수인 결정은 의존 작업을 대기시키고 독립 작업은 계속한다. 시작 시 현재 실행의 대시보드를 직접 열어 표시를 확인한다. 갱신은 반복 조회 대신 변경 알림을 따른다. CMD에는 같은 작업의 `[ ]`/`[x]` 체크리스트를 착수·주요 전환·답변 대기·종료 시 사람이 이해할 문장으로 보고한다. 대시보드 완료 표시가 CMD 보고를 대신하지 않는다.

## 종료 맥락 정리

[산출물 관리 규칙](artifact-policy.md)에 따라 현재 명세·맥락은 유효 기준으로 갱신하고, 의미 있는 작업은 [작업 기록](work-items/README.md) 하나에서 이유·결정·검증·변경을 연결한다. 과거 결과를 현재 결과로 덮어쓰거나 이력을 현재 맥락에 누적하지 않는다. 커밋 준비는 [커밋 규칙·자동 훅](commit-policy.md)을 따른다.

기능·정책·데이터/API 계약·아키텍처 변경은 구현·필요 검증 후 실제 맥락 정리 서브에이전트를 호출한다. 담당은 관련 기준과 [현재 맥락](fresh-memo/context.md)을 대조하고 사용자 확정·제안·구현·미해결을 구분한다. 원문·과거 결정·실패/검토 근거를 보존하고 대체 관계를 연결한다. 제품 코드·핵심 정책을 이 책임으로 바꾸지 않는다.

담당은 수정 경로·현재 SHA-256·이유·남은 제안/문제와 UPDATED/NO_CHANGE를 반환한다. 메인이 변경을 읽고 별도로 수락하며 담당 결과를 사용자 승인으로 대신하지 않는다. 단순 오타·기계적 수정은 메인이 갱신하고 해당 작업에 예외 이유를 남긴다. 정리 담당 자신에게 재귀 위임하지 않는다.

## 사용량과 완료 근거

실행에 정확한 native session/turn 또는 response ID를 연결한다. 자식은 실제 native ID·호출 근거로 연결하고 이름·시간·경로로 추정하지 않는다. 미확인은 UNKNOWN이다. 원본 수집·사용량 수치·실행 바인딩을 각각 확인하며 누적 스냅샷·캐시·추론 상세를 추가 합산하지 않는다.

프로젝트 `.harness/completion-policy.json`은 PRODUCT/HARNESS_IMPROVEMENT 신규 작업에 사용량·맥락 점검을 요구한다. 감시 문서는 AGENTS.md·현재 맥락·이 운영 지침이다. 구성한 완료 계약은 사용량 연결·정리 결과·메인 수락·현재 문서 해시를 검사한다. 기존 완료를 소급 변경하거나 pending·충돌·미확인을 PASS로 보고하지 않는다. 이는 구조적 근거 검사이며 자동 담당 생성·사용자 승인·전체 수집 보장은 아니다. 마지막 응답은 종료 수집 이후 갱신될 수 있다.

## 버전 필터와 착수·답변 게이트 적용 (2026-10-30)

선택 설치 커밋은 `799a4a529621f393e8566669ed9fecbe60aac018`이다. 코드·설치·실제 startup/hook 활성화는 별개다. 현재 startup 재로드 `NOT_RUN`·runtime `RESTART_REQUIRED`를 유지하고 새 프로젝트 세션에서 실제 검증한다.

이번 정리에서 메인이 원격 main `c2b5a52c0c906bbb20ccee59138117032b476932`의 PR #5 병합을 확인했다. 과거 PR 미머지 관측과 구분한다. 메모리·로컬 검증 정책은 공통 커밋 `2ef4b0e29020025a391ebae35145d31183610dfc`와 [Draft PR #6](https://github.com/wooyj-1217/kmp_agent/pull/6)으로 제출했다. 아직 미머지·미배포이며 실제 프로젝트 선택 설치는 바꾸지 않았다. [작업 기록](work-items/2026/2026-10-30-memory-history-rollout.md)에서 검증·제출 상태를 확인한다.

- 버전 필터는 실행 시작 identity와 기간·scope·project 교집합을 사용한다. 누락·충돌은 UNKNOWN이며 일부 실행으로 전체 완료를 승격하지 않는다.
- 활성 managed 경로는 현재 실행의 전체·담당 계획과 메인 native 연결을 확인한다. 필수 답변은 의존 작업만 대기시키며 실제 인간 출처·질문 연결을 검증한 명시 선택형만 해제한다. FREEFORM 해제는 미지원이다.
- 실제 신규 인간 답변 수신 검증은 `NOT_RUN`이다. 기존 실행의 사후 계획 연결을 착수 당시 guard 통과로 바꾸지 않는다. raw shell·OS 전체 통제, 외부 효과 복구를 보장하지 않는다.
- 현재 커밋의 전체 회귀 판정은 `.harness/version-gates/validation.json`의 대상 커밋·결과를 확인한다. 과거 커밋 수치를 현재 PASS로 승계하지 않는다. 상세 설치·QA·사용량 정정은 [보존 이력](work-items/2026/2026-10-30-harness-operations-history.md#운영-지침-원문)에 있다.

이 운영 상태는 여백 서버 동기화나 제품 전체 요구의 완료를 뜻하지 않는다. PR·릴리스 상태는 실제 대상에서 확인하며 역사 기록의 미머지 관측을 현재 상태로 단정하지 않는다.

## 증거 보존과 버전업 정리

최신 사용자 결정에 따라 검증 원본 로그·캡처·JSON·묶음은 기존 로컬 경로에서 확인·보존한다. Git 커밋·PR 첨부·원격 보관소에 업로드하거나 기존 증거를 삭제·이동하지 않는다. PR에는 코드·문서와 실제 검증 명령·결과 요약만 남긴다. 과거 증거 전체를 일반 실행의 필수 입력으로 삼지 않고 원본 미확인은 그 한계를 기록한다.

PR 준비·리뷰 중 증거를 유지하고, 버전업 때 반영 작업의 목록·중복·참조 상태만 점검한다. 중요 원본·미반영·미해결 근거는 보존하며 실제 삭제·이동은 향후 별도 명시 지시가 필요하다. 이 점검은 증거 정리 권한이나 원격 백업·복구 도구 채택을 뜻하지 않는다. [보존 규칙](artifact-policy.md#에이전트-수정-증거의-수명-주기)과 [현재 작업 기록](work-items/2026/2026-10-30-memory-history-rollout.md)을 따른다.
